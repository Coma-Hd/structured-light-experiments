## 2. 本次机械与坐标系方案

### 2.1 机械关系

当前机械方式：

```text
物体固定
ChArUco 标定板固定在物体下面
相机与线激光器刚性连接
相机+激光器随电动导轨做连续直线运动
切换物体面时，整条导轨与相机+激光组件一起转位
```

四次扫描期间禁止移动：

```text
物体
ChArUco 标定板
物体与标定板之间的相对位置
```

可以移动：

```text
整条导轨
刚性连接的相机+激光组件
```

### 2.2 为什么固定标定板后不再需要手填 rail.axis

每张有效图片都能通过可见的 ChArUco/ArUco 角点求出：

```text
标定板 -> 相机的旋转 R
标定板 -> 相机的平移 t
```

相机光心在标定板坐标系中的位置为：

```text
C_board = -R^T t
```

同一次扫描中，相机应保持姿态固定并沿直线移动，因此程序对所有有效帧拟合：

```text
C_board(s) = C0 + (s - s0) × motion_per_nominal_distance
```

由此自动得到：

```text
本次导轨在标定板坐标系中的方向
实际位移/名义位移比例
平滑后的每帧相机位置
平均相机姿态
```

激光点随后直接变换到标定板坐标系：

```text
P_board = R^T(P_camera - t)
```

因此：

1. 不要求导轨严格沿相机 X/Y 轴。
2. 不需要人工填写真实三维 `rail.axis`。
3. 每次整轨转位后可以自动重新求导轨方向。
4. 不要求被测物体是正方体。
5. 四个面的点云天然具有共同的标定板坐标系。

## 4. 今日技术路线变化

### 4.1 最初方案：依赖手填导轨向量

最初重建公式：

```text
P_world = P_camera + (s - s_ref) × rail.axis
```

初始近似：

```yaml
rail:
  axis: [1.0, 0.0, 0.0]
```

问题：

```text
Face2 只重建一部分
单次扫描得到的两个面不是 90°
拼接会选择几何上错误但 ICP fitness 较高的候选
实际导轨方向无法保证严格沿相机坐标轴
电机实际速度与名义速度可能存在比例误差
```

经过方向检查后，旧轨道模式的近似轴曾修正为：

```yaml
rail:
  axis: [-1.0, 0.0, 0.0]
```

该修正曾使部分角度由约 `68°` 改善到约 `85°`，但它仍然只是近似，不能解决完整三维运动与尺度问题。

### 4.2 ROI 问题

旧 Face2 使用固定手工三维 ROI，导致大面积真实点被裁掉。

修正：

```yaml
roi:
  enabled: true
  mode: "auto"
```

并增加：

```text
auto_z_bins
auto_z_pad_m
auto_xy_pad_m
auto_percentile_lo
auto_percentile_hi
```

要求：

```text
cloud_clean.ply 必须保留主面
必须保留相邻面条带
必须保留连续共享棱
不能在拼接前只提取最大平面
```

### 4.3 正方体自标定尝试

曾增加：

```text
scripts/calibrate_cube_motion.py
```

优化变量：

```text
motion_per_nominal_distance
rail.axis
distance_scale
```

约束：

```text
两个平面分别平整
两个平面夹角为 90°
轴方向与初值不要偏离过大
速度比例不要偏离名义值过大
```

该方法可用于没有标定板的旧正方体数据，但存在不可观测方向：

```text
沿两个平面公共棱方向的运动分量同时平行于两个面，
不会破坏两个面的平整度或 90°，仅凭两个面不能唯一确定。
```

因此它只保留为旧数据补救方案，不作为当前首选。

### 4.4 最终方案：固定板在线导轨拟合

最终改成：

```yaml
pose_source: "charuco"

charuco_tracking:
  mode: "rail_fit"
  min_pose_frames: 8
  min_pose_span_m: 0.030
  min_corner_area_ratio: 0.002
  max_center_residual_m: 0.004
  max_rotation_deviation_deg: 1.5
```

每次扫描：

1. 检测所有可见标记角点。
2. 计算标定板到相机位姿。
3. 将相机光心转换到板坐标系。
4. 鲁棒拟合直线轨迹。
5. 剔除相机中心或姿态异常的帧。
6. 为所有保存帧生成平滑位姿。
7. 将激光点统一到固定板坐标系。


```text

局部板可见时，solvePnPRansac 使用最小子集容易选中错误平面解。
```

文件：

```text

```

修改为：

```text
使用所有检测点执行 SOLVEPNP_ITERATIVE
不再对该共面板使用 solvePnPRansac 选最小子集
后续使用整体重投影误差和跨帧直线轨迹剔除异常
```

修正后抽样结果：


## 7. 错误三：激光平面标定使用了板外激光

### 7.1 原始错误

激光标定图片中，蓝线同时落在：

```text
ChArUco 标定板
标定板前方地毯
背景物体
```

旧代码对整幅图提取激光中心，然后把所有激光射线都与“无限延伸的标定板平面”求交。

这是错误的，因为：

```text
只有真正落在实体标定板上的激光像素才位于 board_plane。
地毯上的激光像素不能与 board_plane 求交后当成激光三维点。
```

该错误可能得到：

```text
RANSAC RMS 看似较低
但激光平面真实位置严重错误
```

### 7.2 直接验证

在 Face1 当前扫描图中选取肉眼确定落在标定板上的激光点：

```text
像素约：(471, 590)
```

旧激光平面将它重建到：

```text
离标定板约 106 mm
```

旧激光平面预测该图像行上的板面激光位置：

```text
预测 x ≈ 352 px
实际 x ≈ 471 px
偏差约 119 px
```

这直接证明旧 `laser_plane.yaml` 不对应当前真实激光几何。

### 7.3 修正

文件：

```text
src/calib_laser_plane.py
```

新增：

1. 计算当前帧检测角点的二维凸包。
2. 只保留凸包内部的激光中心。
3. 标定板外的地面、墙面和物体激光全部排除。
4. 增加单帧 ChArUco 重投影误差门限。
5. 增加激光平面总内点率门限。

关键原则：

```text
板外激光不能与无限延伸的板平面求交。
```

## 15. 故障排查表

### 15.1 ChArUco 有效位姿为 0，但检测数量很多

检查拒绝统计：

```text
reprojection_error 全部增加
```

处理：

```text
确认当前使用全点 ITERATIVE PnP
确认标定板尺寸、字典和 ID 排布
抽查单帧重投影误差应约 1 px
```

### 15.2 `corners_too_clustered` 很多

原因：

```text
只露出一条窄标定板
角点几乎共线
物体遮挡过多
```

处理：

```text
增加板的可见宽度和高度
让可见角点分布在二维区域
每次扫描保证至少 8 个有效位姿覆盖 30 mm
```

### 15.3 单次点云夹角明显不是 90°

依次检查：

1. 使用 RANSAC 实测点云平面夹角，不要只看查看器透视。
2. 比较 `rail_fit` 与每帧原始 PnP；若都错，问题不在轨迹平滑。
3. 用扫描图中肉眼确定的板面激光验证其重建后是否接近 `Z=0`。
4. 检查激光平面是否混入板外激光。
5. 检查激光标定目录是否混入不同批次。
6. 检查相机/激光刚性安装是否在标定后发生变化。

### 15.4 激光平面 RMS 很低，但实体角度仍错误

不能只看内点 RMS。

同时检查：

```text
平面内点率
是否只用了同一批图片
是否只使用板内激光
当前板面激光的实际深度误差
已知直角件重建夹角
```

### 15.5 ICP fitness 很高但拼接姿态错误

原因：

```text
正方体或平面对称
```

必须同时检查：

```text
锚点是否对应同一物理端点
anchor RMSE <= 10 mm
ICP 相对初值旋转变化 <= 15°
彩色接缝是否出现双线
```

### 15.6 第二个面被裁掉

检查：

```text
roi.mode 是否为 auto
关键帧 ROI 是否覆盖完整目标面和邻面条带
```

## 18. 后续问题一：Face3 棱边出现卷曲和鼓包

### 18.1 现象

Face3 重建后整体两个主平面方向正确，但共享棱附近出现局部弯曲、鼓包和桥接点，视觉上像棱角被卷起。

最初需要区分两类问题：

```text
整体几何错误：
  导轨轨迹、ChArUco 位姿或激光平面错误

局部棱边错误：
  激光跨棱时出现双响应、反光或中心线跳变
```

Face3 的轨迹报告：

```text
有效位姿：222 / 222
轨迹行程：110.55 mm
center_fit_rms：0.704 mm
max_rotation_deviation：0.294°
mean_reprojection_error：0.978 px
accepted：true
```

平面分析得到两个主平面夹角约 `88.04°`，说明整体轨迹和三维方向基本正确，异常主要集中在棱边附近。

### 18.2 根因

激光横跨真实棱边时可能同时照亮两个面。木材散射、过曝和多路径反光会形成多个激光响应峰。

当前 Steger 中心线提取每行只选择一个主要响应，棱边处可能发生：

```text
前几行选择 P2 上的激光
下一行突然选择 P3 上的激光
smooth_window 又把两段跳变连接
最终生成弯曲的三维“桥”
```

这不是整个平面角度错误，而是不可信的局部混合测量。

### 18.3 增加双平面清理

在 `src/postprocess.py` 中新增 `two_plane_cleanup_mask()`：

```text
1. RANSAC 找点数最多的第一个主平面。
2. 移除第一平面内点，继续寻找方向不同的第二平面。
3. 计算每个点到两个平面的距离。
4. 删除同时远离两个主平面超过门限的点。
5. 不投影保留点，不强制两个面为 90°。
6. 找不到可靠双平面或保留点过少时自动回退。
```

Face3、Face4 配置：

```yaml
postprocess:
  two_plane_cleanup:
    enabled: true
    ransac_threshold_m: 0.0015
    max_distance_m: 0.002
    min_plane_points: 500
    min_plane_angle_deg: 45.0
    min_keep_fraction: 0.70
    ransac_iterations: 4000
```

重要原则：

```text
只删除不可信点
不把点压到理想平面
不使用正方体 90° 先验
不修改保留点坐标
```

### 18.4 Face3 实际结果

重新运行 Face3 重建：

```text
两个主平面：12928 / 8323 点
夹角：87.83°
ROI 后：25068 点
双平面清理后：22198 点
删除混合/反光点：2870 点
体素与 SOR 后：21355 点
```

清理后原来的弯曲桥接明显减少。棱边处可能留下小缺口，这是删除不可信测量后的正常结果，不能用插值伪造不存在的可靠激光中心。

该功能只适合明确的双平面物体。自由曲面、圆柱、雕刻和真实缺陷检测必须关闭。

### 20.1 现象

`board_merged.ply` 能形成大致四边形轮廓，但部分相邻面之间存在明显断点。Face1/Face2 连接较好，Face3/Face4 一侧尤其明显。


```text
merge_face_chain.py
6_merge_face_chain.ps1
Face2→Face1、Face3→Face2、Face4→Face3 的变换组合
```

### 20.2 这个链式思路为什么不完整

后续重新检查实际拍摄定义后发现，之前把：

```text
物体物理面编号
扫描批次编号
```

错误地当成同一件事。

最初成功的 P1/P2 拼接实际上使用了两次互补扫描：

```text
第一次：P1 主面 + 部分 P2
第二次：部分 P1 + P2 主面
```

按相同逻辑，P2/P3 应该使用另外两次扫描：

```text
第三次：P2 主面 + 部分 P3
第四次：部分 P2 + P3 主面
```

因此简单把“第三次扫描”解释成 P3、把“第四次扫描”解释成 P4，再做 `Face2→Face3→Face4` 链式 ICP，不等价于为每条物理棱建立互补观测。

### 20.3 四边互补扫描需要八次

四个物理面记为 P1～P4，四条共享棱为 E12、E23、E34、E41。

完整互补序列：

```text
E12-A：P1 主面 + 部分 P2
E12-B：部分 P1 + P2 主面

E23-A：P2 主面 + 部分 P3
E23-B：部分 P2 + P3 主面

E34-A：P3 主面 + 部分 P4
E34-B：部分 P3 + P4 主面

E41-A：P4 主面 + 部分 P1
E41-B：部分 P4 + P1 主面
```

所以：

```text
4 条共享棱 × 每条 2 次互补扫描 = 8 次扫描
```

### 20.4 八次路线最后仍需要闭环

每条棱先得到一个局部边对：

```text
Pair12、Pair23、Pair34、Pair41
```

四个边对之间通过完整物理面重叠：

```text
Pair12 与 Pair23 共享 P2
Pair23 与 Pair34 共享 P3
Pair34 与 Pair41 共享 P4
Pair41 与 Pair12 共享 P1
```

最终必须做四边全局位姿图优化，不能只顺序累乘变换，否则误差会集中在最后的闭环。

因此：

```text
6_merge_face_chain.ps1 不能作为八次互补扫描的最终工具
它也不能修复激光平面错误造成的非刚性三维偏差
```

保留该实验代码用于参考，但当前正式流程不再推荐执行。

```text
激光平面负责：
  把 Face4 图像中的激光像素变成相机坐标三维点

ChArUco 负责：
  把新的 Face4 三维点变换到相同板坐标系
```

因此激光平面可以按安装状态分别版本化：

```text
output/laser_plane_before_face4.yaml
output/laser_plane_face4.yaml
```

处理顺序：

```text
1. 锁紧相机、激光头和支架。
2. 备份旧 laser_plane.yaml。
3. 在当前安装状态重新标定激光平面。
4. Face1～Face3 不重新重建。
5. Face4 配置只引用新激光平面。
6. 丢弃旧 Face4，重新采集和重建。
7. 再执行板坐标直接合并。
```

最好使用另一块标定板重新标定，不要为了标定取下物体。若物体取下后重新摆放，物体相对底板的公共坐标关系无法保证。

## 23. 最终整理出的两条正式路线

### 23.1 路线 A：八次互补扫描

标定板放在物体下面，主要用于：

```text
确定每次导轨移动方向
估计实际/名义位移比例
拟合连续轨迹
```

最终拼接依靠：

```text
每条棱两次互补扫描
共享棱顶部/底部锚点
双平面初值
多尺度 ICP
四边全局闭环
```

适用于不信任不同扫描之间板坐标绝对位置的情况。

### 23.2 路线 B：四次固定板绝对定位

标定板同时用于：

```text
确定导轨移动方向和尺度
确定物体在所有扫描中的公共位置
```

只要物体和板保持固定：

```text
P1、P2、P3、P4 各扫描一次
四份点云直接在板坐标系合并
不需要八次互补扫描
```

正常需要四次。若只有某一面因机械或标定问题失败：

```text
修复问题
只补拍失败面一次
最多共五次
```

如果物体相对板已经移动，则不能只补拍一个面，公共坐标关系已经失效。

## 25. 当天最终结论

今天后半段最重要的修正不是继续增加 ICP，而是重新区分：

```text
物理面
共享棱
扫描批次
板坐标轨迹
板坐标绝对物体位置
相机—激光刚性关系
```

最终判断：

```text
Face1/Face2 成功结果有效
Face3 局部卷曲可通过删除不可信双平面外点改善
四面直接合并脚本已修复并可正确读取全部点云
当前四面断点主要由 Face4 系统偏差造成
逐帧 ChArUco 不能修复 Face4，说明问题不在 rail_fit
Face4 最可能在转位时破坏了相机—激光相对刚性
现有四扫描顺序链不能代替八次互补扫描闭环
```

当前最合理的下一步：

```text
继续采用四次固定板绝对定位路线
锁紧相机、激光头和支架
备份旧激光平面
重新标定当前安装状态
只重拍 Face4
再次执行板坐标直接合并
```

如果后续确认固定板绝对定位无法达到要求，再切换到八次互补扫描路线，并为四条共享棱建立完整的全局闭环，而不是继续使用错误的四扫描链式累乘。

## 26. 7月21日补充：白紫激光核心与四面共同外扩

新一批图像中发现，激光高亮核心因过曝呈白色或白紫色，而旧 `blue_minus_green` 更容易选择旁边的纯蓝光晕。

Face1 中间帧实测：

```text
旧 Steger 中心相对最亮白紫核心偏约 3 px
3.5 px 像素变化对应约 6.82 mm 三维变化
其中深度变化约 5.86 mm
```

新增响应：

```text
blue_weighted_intensity
score = mean(B,G,R) × max(B-G,0) / 255
```

它仍用蓝色增量排除普通白色背景，但用亮度把中心拉向白紫核心。测试中到白紫核心的中位偏差由约 `3 px` 降至约 `1 px`。

同时发现旧配置存在风险：

```text
激光平面标定使用项目 config.yaml
四面重建使用 face1～face4_scan.yaml
两者的 score_mode 和 Steger 参数并不完全相同
```

激光平面标定与正式扫描若使用不同中心定义，会把固定像素偏差放大成毫米级深度偏差。

新一批四面对距离：

```text
Face1 → Face2：1% 分位 17.06 mm
Face2 → Face3：1% 分位 23.93 mm
Face3 → Face4：1% 分位 13.96 mm
Face4 → Face1：1% 分位 10.60 mm
```

四个面都向外散开，符合共同深度偏差，而不像单个板坐标轴错误。视觉上分别向内平移能闭合，但这四个方向不同的平移不是一个合法公共坐标变换，不能作为最终修正。

已完成：

```text
src/laser_center.py 新增 blue_weighted_intensity
config.yaml 与四份 face 配置统一激光响应参数
生成 check_098_white_core.png 验证红点更接近白紫核心
```

下一步必须：

```text
使用统一后的 config.yaml 重新标定激光平面
旧 laser_plane.yaml 作废
用新平面重新重建四面
重新执行板坐标直接合并
再判断是否仍存在公共坐标系偏差
```
