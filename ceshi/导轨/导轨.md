# 曲面单面扫描

该目录是独立的曲面扫描工作区。曲面采集图片、位置记录、五关键帧 ROI、检查图、标定副本和重建结果都保存在本目录下，不再引用 `ceshi/rail` 的数据路径。

## 首先进入正确的测试包根目录

本文中的“项目根目录”是包含 `.venv`、`scripts`、`src`、`install.ps1` 和内层 `ceshi` 的测试包目录。当前电脑上从外层工程目录进入时，先执行：

```powershell
Set-Location .\ceshi
```

此时应能同时看到：

```text
.venv/Scripts/python.exe
scripts/capture.py
ceshi/曲面/curve_scan.yaml
```

后续命令均从这个目录执行。不要在外层目录调用外层的 `scripts/capture.py`，否则 `ceshi/曲面/curve_scan.yaml` 会解析到错误位置。

第一次使用或 `.venv` 缺少依赖时，先执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Action setup
```




## 默认相机参数

曲面扫描、内参采集和激光平面标定统一使用：

```text
Exposure = -4
Gain = 10
Resolution = 800 x 600
```

采集开始后不要再修改曝光或增益。当前 `calibration` 中的 YAML 是此前标定结果的副本；切换到上述新参数后，至少必须重新标定激光平面。若相机分辨率、镜头、焦距或对焦发生变化，也必须重新标定内参。

## 相机内参标定

在上述测试包根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts/capture.py `
  --config ceshi/曲面/curve_scan.yaml `
  --out ceshi/曲面/data/calibration/intrinsic `
  --mode shot `
  --cam 1 `
  --width 800 `
  --height 600 `
  --exposure -5 `
  --gain 7
```

移动 ChArUco 板拍摄约 20～30 张清晰图片，覆盖画面中心、四角、远近和不同倾角。避免运动模糊、反光和严重过曝。采集完成后：

```powershell
.\.venv\Scripts\python.exe scripts/1_calibrate_intrinsic.py `
  --config ceshi/曲面/curve_scan.yaml `
  --images ceshi/曲面/data/calibration/intrinsic `
  --out ceshi/曲面/calibration/camera_intrinsic.yaml
```

确认输出分辨率为 `800 x 600`，并检查重投影误差。

## 激光平面标定

保持相机、激光和镜头完全不动。使用与正式扫描完全相同的曝光、增益和激光中心参数：

```powershell
.\.venv\Scripts\python.exe scripts/capture.py `
  --config ceshi/曲面/curve_scan.yaml `
  --out ceshi/曲面/data/calibration/laser_plane `
  --mode shot `
  --cam 1 `
  --width 800 `
  --height 600 `
  --exposure -6 `
  --gain 7
```

开始新一批标定前先清空 `data/calibration/laser_plane`，不得让不同增益或不同安装状态的图片留在同一目录。打开激光后：

1. 把 ChArUco 纸张完整粘贴在刚性平板上，不要只用手捏住一角；纸张弯曲会让程序估计出的“板平面”逐帧变化。
2. 在近、中、远多个距离以及绕水平、竖直两个方向的不同倾角下拍摄，不能只连续拍大量相似姿态。
3. 每次移动后完全静止，再拍一张；激光必须落在实体标定板内。
4. 建议 15～25 个几何差异明显的有效姿态，并覆盖正式扫描的完整工作距离。

然后执行：

```powershell
.\.venv\Scripts\python.exe scripts/2_calibrate_laser_plane.py `
  --config ceshi/曲面/curve_scan.yaml `
  --images ceshi/曲面/data/calibration/laser_plane `
  --intrinsic ceshi/曲面/calibration/camera_intrinsic.yaml `
  --out ceshi/曲面/calibration/laser_plane.yaml
```

不得混用旧曝光、旧增益、旧激光响应或其他安装状态的标定图片。标定完成后检查 `fit_rms_m`，并优先使用未参与拟合的板姿态做深度留出验证。

程序会先按“整帧激光交线”自动寻找共面帧，再执行点级 RANSAC。若提示只有少量图片属于同一激光平面，不能通过降低 `min_inlier_ratio` 强行保存；应根据输出的被拒绝文件重新检查板刚性、运动模糊、饱和和姿态覆盖。

2026-07-24 失败批次 `img_178487793...` 的实际拍摄参数被从命令行 Gain=15 手动升到了 Gain=20；50 张中只有 4 张在 1 mm 阈值下形成整帧共识，因此该批数据不可用于正式标定。

### 激光线宽与质量过滤

当前配置会在激光平面标定和正式扫描中统一执行：

```text
半高宽范围：1～90 px（新相机白芯和木材弱蓝响应更宽，中心仍由 Steger 定位）
连续饱和宽度：最多 20 px
第二峰/主峰：最多 0.95（动态掩码已排除背景，避免材质肩峰造成断点）
连续性窗口：5 行/列
中心相对局部中位数最大偏差：4 px
```

新相机把激光核心拍成白色时使用 `blue_guided_intensity`：先由周围蓝色光晕确定激光邻域，再在该邻域内按亮度定位白色核心，避免红点吸附到蓝色光晕的一侧。修改该响应模式后必须重新标定激光平面。

过宽、严重饱和、存在相近第二峰或相邻行突然跳变的中心会被拒绝。激光平面标定还会：

1. 使用受蓝激光影响更小的绿色通道检测标定板，激光中心仍从完整彩色图提取。
2. 在提取中心前先把响应限制到 ChArUco 角点凸包内，防止板外强激光抢走逐行最大值。
3. 使用另一台电脑成功版本中的标定专用过滤：响应低于 40 的中心被拒绝，并用二维 RANSAC 只保留距主条带不超过 2.5 px 的点。
4. 位姿估计排除激光中心 10 px 范围内的 ChArUco/ArUco 角点，防止蓝线覆盖标记后拉偏板位姿。
5. 每帧用 RANSAC 拟合三维激光交线，拒绝偏离直线超过 1 mm 的局部中心，并将内点投影回物理交线。
6. 每个板姿态最多均匀保留 120 个高质量中心，避免激光可见长度更大的姿态支配拟合。
7. 跨帧按整条交线寻找共同激光平面，整帧异常不会再靠较多像素支配结果。

标定日志中的：

```text
使用(选中点数/检测点数 激光点, 线RMS=..., 板角点=保留/检测)
```

可用于检查过滤强度。如果多数图片选中点少于 `min_laser_points`，不要只放宽 RANSAC；应先检查曝光、激光焦距、线宽和板内激光是否连续。修改上述任一质量门限后，必须重新标定激光平面，并以同一配置正式扫描。

## 曲面扫描顺序

在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/曲面/0_capture.ps1 `
  -VelocityMmS 1.0 `
  -Cam 1 `
  -StepMm 0.2 `
  -Width 800 -Height 600 `
  -Exposure -7 `
  -Gain 7 `
  -ClearOutput
```

采集完成后，在扫描序列的5张关键帧中分别手动画矩形 ROI，并执行 laser check：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/曲面/1_draw_check.ps1
```

如果原始图片和 `positions.csv` 没有变化，只修改了激光中心门限，可复用现有五框 ROI：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/曲面/1_draw_check.ps1 `
  -ReuseRoi
```

程序会自动选择扫描起点、终点及中间位置共5张关键帧。每张图都执行：

```text
鼠标左键拖拽：画出仅覆盖物体激光区域的矩形
ENTER / SPACE：确认当前框并进入下一张
R：重画当前框
S：跳过当前关键帧
Q / ESC：结束
```

五个矩形会与对应的 `distance_mm` 一起写入：

```text
work/roi_keyframes.json
```

重建和 laser check 会根据每帧在 `positions.csv` 中的导轨位置，在前后两个关键帧矩形之间线性插值，不再生成或读取物体掩码。

输出：

```text
work/roi_keyframes.json
work/laser_check/check_*.png
```

逐张检查 `work/laser_check`：

- 当前插值矩形必须覆盖完整的物体激光。
- 红点贴合激光亮核。
- 红点不能进入标定板、背景或反光。
- 若同一图像行出现多段独立激光，当前单分支 Steger 可能漏掉其中一段，应停止重建并先升级提取算法。

当前配置为 `keyframe_roi.enabled: true`、`object_mask.enabled: false`。
旧的 `work/object_masks/manifest.json` 即使仍存在，也不会参与激光提取或重建。
每次重新采集后必须重新画5个框；`0_capture.ps1 -ClearOutput` 会删除旧
`roi_keyframes.json`，防止新图片误用上一批 ROI。

检查通过后：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/曲面/2_rebuild.ps1
```

最终查看：

```text
ceshi/曲面/output/cloud_clean.ply
ceshi/曲面/output/inspect_clean/
```



## 固定的半球精度验证

重建完成后，不再用坐标轴跨度估算直径。执行统一的稳健球面拟合、真实尺寸误差、形状残差和 ChArUco 轨迹检查：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/曲面/3_validate_hemisphere.ps1 `
  -DiameterMm 98.9
```

程序优先读取当前 `output/cloud_clean.ply`，不存在时读取 `output/cloud.ply`，并生成：

```text
ceshi/曲面/output/validation/hemisphere_validation.md
ceshi/曲面/output/validation/hemisphere_validation.json
```

也可以检查已经归档到子目录的单次扫描：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/曲面/3_validate_hemisphere.ps1 `
  -DiameterMm 98.9 `
  -Inputs "ceshi/曲面/output/7.24下午测试/1/cloud.ply" `
  -ReportName "7.24下午_第1次"
```

报告固定包含：

- 稳健球面拟合半径、直径以及相对真实值的 mm/% 偏差。
- 球面径向残差中位数、RMS、P95、0.5 mm 和 1 mm 通过率。
- 点数、球面内点率和 XYZ 可见区域跨度。
- ChArUco 有效帧、轨迹中心 RMS、最大残差、旋转偏差和重投影误差。
- 本次内参重投影误差与激光平面拟合 RMS。

坐标轴跨度只是当前可见区域的包围盒，不等于直径；球面形状残差也不等于绝对尺寸误差。

## 多次扫描重复性验证

每次扫描完成后，先把该次 `cloud.ply`、`cloud_clean.ply` 和 `cloud_charuco_tracking.yaml` 一起复制到独立子目录，不能被下一次重建覆盖。然后把多次点云一次性传入：

```powershell
$Clouds = @(
  "ceshi/曲面/output/7.28下午测试/1/cloud.ply",
  "ceshi/曲面/output/7.28下午测试/2/cloud.ply",
  "ceshi/曲面/output/7.28下午测试/3/cloud.ply"
)
$CloudList = $Clouds -join ";"

powershell -ExecutionPolicy Bypass `
  -File ceshi/曲面/3_validate_hemisphere.ps1 `
  -DiameterMm 98.9 `
  -InputList $CloudList `
  -ReportName "hemisphere_repeatability"
```

注意：通过 `powershell -File` 启动子进程时不能直接传递外层 PowerShell 数组；必须按上面方式用 `-InputList` 传递分号分隔的单个字符串。若在当前 PowerShell 会话中直接使用调用运算符 `&` 执行脚本，则仍可使用 `-Inputs $Clouds`。

除每次的单独指标外，多次报告还包含：

- 拟合直径均值、样本标准差和极差。
- 多次扫描的平均绝对尺寸偏差。
- 两两拟合直径差和球心距离。
- ChArUco 板坐标系下、不执行 ICP 的双向最近邻中位数、RMS 和 P95。
- 自动共同覆盖区域拟合：默认先去除各点云 XYZ 两端 2% 边缘，再取板坐标公共交集，消除手动停止行程不同造成的覆盖偏差。

报告同时保留两套结果：

1. `共同覆盖区域重复性`：作为不同停止行程下的主要重复性判定指标。
2. `完整点云重复性`：用于暴露扫描起止范围、ROI 和边缘杂点差异，不能被共同区域结果覆盖。

如需调整共同区域边缘裁剪比例：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/曲面/3_validate_hemisphere.ps1 `
  -DiameterMm 98.9 `
  -InputList $CloudList `
  -CommonOverlapPercentile 2 `
  -ReportName "hemisphere_repeatability"
```

输出：

```text
ceshi/曲面/output/validation/hemisphere_repeatability.md
ceshi/曲面/output/validation/hemisphere_repeatability.json
```



## 约束

- 曲面和 ChArUco 板在扫描过程中必须保持刚性固定。
- 保持当前相机、激光安装状态不变。
- `score_mode`、门限和 Steger 参数必须与激光平面标定一致。
- `calibration` 中保存本曲面流程正式使用的标定结果，不能再引用或混入其他目录的 YAML。
- 当前配置关闭三维自动裁剪、平面提取、双平面清理和网格生成，避免把真实曲率误删或压平。
- 单方向看不到的凹槽、背面和激光阴影不能由本次单面扫描恢复。

## PLY 转 OBJ

重建后的主结果是点云 `ply`。若需要网格 `obj`，在测试包根目录执行已有脚本
`scripts/ply_to_obj.py`。

推荐先用清理后的点云：

```powershell
.\.venv\Scripts\python.exe scripts/ply_to_obj.py `
  --in ceshi/曲面/output/cloud_clean.ply `
  --out ceshi/曲面/output/mesh.obj `
  --method bpa `
  --no-roi
```

半球或自由曲面一般用 `bpa`。若只要更平滑的封闭感，可改成：

```powershell
.\.venv\Scripts\python.exe scripts/ply_to_obj.py `
  --in ceshi/曲面/output/cloud_clean.ply `
  --out ceshi/曲面/output/mesh_poisson.obj `
  --method poisson `
  --no-roi
```

说明：

- `--no-roi`：曲面结果通常已在采集/重建阶段用关键帧 ROI 过滤，这里不再二次裁剪。
- `bpa`：适合表面片，默认优先用于半球检查。
- `poisson`：更平滑，但可能补洞或膨胀，尺寸检查仍以 `cloud_clean.ply` 为准。
- 该脚本没有 `--config` 参数；尺寸与形状验证继续看点云，不要只用 `obj` 网格做直径判定。
