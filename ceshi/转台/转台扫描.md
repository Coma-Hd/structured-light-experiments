# 转台连续环绕扫描

该目录用于验证“相机和线激光保持固定、物体在转台上匀速旋转”的环绕扫描。它与未来机械臂带动扫描头绕物体运动具有相同的相对运动几何，可用于提前验证：

- 曲线环绕时线激光能否连续重建；
- 逐帧角度融合是否正确；
- 旋转一圈后首尾能否在不使用 ICP 的情况下闭合；
- 环绕扫描的尺寸、形状和重复性是否接近直线导轨扫描。

这里不会把每帧当成独立点云再做 ICP。每个激光点先在相机坐标系中重建，再按照该帧转台角度绕已标定转轴反向旋转，直接进入第一帧对应的公共坐标系。

## 标定板参数

当前使用的 ChArUco 板：

```text
外形尺寸：300 x 200 mm
横向方格：14
纵向方格：9
方格边长：20 mm
ArUco 边长：15 mm
字典：DICT_5X5_100
```

对应 `turntable_scan.yaml`：

```yaml
charuco:
  squares_x: 14
  squares_y: 9
  square_length: 0.020
  marker_length: 0.014
  dictionary: "DICT_5X5_100"
```

`square_length` 和 `marker_length` 的单位是米。`squares_x/y` 是完整方格数量，
不是内部角点数量。棋盘区域为 `280 x 180 mm`，外形四周各保留约 `10 mm`
边距。

修改上述任意参数后，旧的相机内参、激光平面和转台轴全部失效，必须按以下
顺序重新标定：

```text
相机内参 → 激光平面 → 转台旋转轴
```

## 相机内参标定

关闭激光，将 ChArUco 板刚性粘贴在平整板材上。在测试包根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts/capture.py `
  --config ceshi/转台扫描/turntable_scan.yaml `
  --out ceshi/转台扫描/data/calibration/intrinsic `
  --mode shot `
  --cam 1 `
  --width 800 `
  --height 600 `
  --exposure -6 `
  --gain 1
```

等待相机预览亮度稳定后再拍摄第一张。按 `SPACE` 或 `S` 单张保存，建议拍摄
`20～30` 张清晰图片，覆盖：

- 画面中心和四角；
- 近、中、远距离；
- 水平、俯仰和左右倾斜；
- 尽可能大的成像区域，但标定板必须完整清晰；
- 避免重复拍摄大量相似姿态。

采集前应清空或备份旧的 `data/calibration/intrinsic`，不能混入旧标定板或旧
相机状态的图片。采集完成后执行：

```powershell
.\.venv\Scripts\python.exe scripts/1_calibrate_intrinsic.py `
  --config ceshi/转台扫描/turntable_scan.yaml `
  --images ceshi/转台扫描/data/calibration/intrinsic `
  --out ceshi/转台扫描/calibration/camera_intrinsic.yaml
```

检查：

```text
输出分辨率必须为 800 x 600
平均重投影误差建议不超过 1 px
焦距、主点和畸变参数不能出现明显异常
```

内参标定完成后，相机、镜头、焦距、对焦和分辨率均不能再改变。

## 激光平面标定

保持相机和镜头不动，打开激光。激光平面标定必须使用与正式扫描完全相同的：

```text
Resolution = 800 x 600
Exposure = -6
Gain = 7
激光器位置和焦距
turntable_scan.yaml 中全部 laser 参数
```

采集命令：

```powershell
.\.venv\Scripts\python.exe scripts/capture.py `
  --config ceshi/转台扫描/turntable_scan.yaml `
  --out ceshi/转台扫描/data/calibration/laser_plane `
  --mode shot `
  --cam 1 `
  --width 800 `
  --height 600 `
  --exposure -6 `
  --gain 1
```

采集前清空或备份旧的 `data/calibration/laser_plane`。建议拍摄 `15～25` 个几何
差异明显的有效姿态：

1. ChArUco 纸张必须完整粘贴在刚性平板上；
2. 标定板覆盖正式扫描的近、中、远工作距离；
3. 同时改变水平和竖直倾角，不能只做平移；
4. 每次移动后等待板完全静止；
5. 激光必须落在实体标定板范围内；
6. 避免严重过曝、运动模糊和蓝线覆盖过多标记。

然后执行：

```powershell
.\.venv\Scripts\python.exe scripts/2_calibrate_laser_plane.py `
  --config ceshi/转台扫描/turntable_scan.yaml `
  --images ceshi/转台扫描/data/calibration/laser_plane `
  --intrinsic ceshi/转台扫描/calibration/camera_intrinsic.yaml `
  --out ceshi/转台扫描/calibration/laser_plane.yaml
```

重点检查：

```text
有效姿态和有效激光点数量
每帧激光交线 RMS
跨帧激光平面共识
fit_rms_m（建议不超过 0.001 m）
```

如果只有少数姿态属于同一激光平面，不要通过盲目放宽阈值强行保存。应优先
检查标定板是否弯曲、激光器是否移动、曝光是否一致、蓝线是否严重饱和，以及
各姿态是否覆盖足够的空间范围。

修改 `score_mode`、蓝色门控、Steger 参数、线宽/饱和过滤或连续性过滤后，
激光中心位置可能发生变化，必须重新标定激光平面，并用同一配置正式扫描。

## 原理

当前帧激光点首先通过相机内参与激光平面求交，得到相机坐标：

```text
P_camera
```

设转轴在相机坐标系中的轴上一点为 `C`，轴方向为 `n`，当前帧相对于第一帧转过 `θ`。物体当前点满足：

```text
P_current = C + R(n, θ) · (P_reference - C)
```

所以融合时执行反向旋转：

```text
P_reference = C + R(n, -θ) · (P_current - C)
```

转轴标定负责确定 `C` 和 `n`，`angles.csv` 负责提供每帧的 `θ`。

## 转台控制与编码器角度

采集程序直接占用 HC32 USART3 串口，自动完成电机启动、1 秒控制租约续租、
编码器读取和安全停机。固件的 `axis status` 返回 VCE2755 编码器连续展开的
减速器输出角 `actual_mdeg`，单位为 `0.001°`。

每张图像使用相机帧与串口回复的单调时钟时间戳，在前后两个编码器样本之间
线性插值得到实测角度：

```text
angle_deg = start_deg
    + (当前帧插值 actual_mdeg - 第一帧插值 actual_mdeg) / 1000
```

因此不再要求用名义匀速乘时间估角，也不会把电机开环设定速度直接当成实际速度。
仍需注意：

1. `-AngularVelocityDegS` 是输出轴目标速度，正数对应 `ccw`，负数对应 `cw`；
2. 100:1 减速器及当前固件允许的输出速度范围约为 `0.3..3.6 deg/s`；
3. 程序只需确认编码器持续运动便自动开始，不要求开环速度稳定；
  达到目标实测转角后自动停止电机；
4. 串口和相机必须由本程序独占，采集时不要同时打开“J1 开环慢速转动”GUI；
5. 编码器可以反映丢步和速度波动，但物体相对台面打滑仍无法由轴编码器发现；
6. 串口传输延迟和相机实际曝光时刻仍可能形成小量同步误差。

串口固定为 `115200 8N1`。连接后必须收到
`Hello HC32F448 position control`，否则程序不会启动电机。

## 第一步：标定转台旋转轴

### 安装 ChArUco 板

将刚性 ChArUco 板固定在转台上：

- 板与转台必须完全刚性连接；
- 板不能翘曲；
- 板原点不要正好位于转轴上，应偏离转轴一段距离，让板原点画出明显圆弧；
- 相机在至少 `90°` 的旋转范围内都能检测到足够角点；
- 标定转轴时可以关闭激光，避免激光覆盖标记。

标定过程中相机、镜头和转台位置不能移动。

### 采集转轴标定图片

假设 HC32 串口为 `COM10`、目标输出轴速度为 `1 deg/s`：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/转台扫描/0_axis_capture.ps1 `
  -MotorPort COM10 `
  -AngularVelocityDegS 1 `
  -StepDeg 2 `
  -MaxRotationDeg 180 `
  -Exposure -6 `
  -Cam 1 `
  -Gain 7 `
  -ClearOutput
```

操作顺序：

1. 确认电机控制 GUI 和其他串口工具已经关闭；
2. 运行命令后，程序握手并自动启动转台；
3. 编码器检测到持续运动后自动保存第一张图并以该角度为零点；
4. 编码器累计达到 `180°` 后自动停止录制和电机；
5. 需要提前结束时按 `SPACE`、`S`、`Q` 或 `ESC`，程序仍会安全停机。

如果该方向在后续被定义为负方向，则从标定开始就传入负角速度，例如：

```powershell
-AngularVelocityDegS -2
```

生成：

```text
data/calibration/turntable_axis/img_*.png
data/calibration/turntable_axis/angles.csv
data/calibration/turntable_axis/continuous_capture_report.json
```

### 计算转轴

执行：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/转台扫描/1_calibrate_axis.ps1
```

输出：

```text
calibration/turntable_axis.yaml
```

重点检查日志中的：

```text
有效位姿数量
角度覆盖
中心模型 RMS / 最大值
旋转模型 RMS / 最大值
PnP 平均重投影误差
```

脚本会在控制台逐项显示数值、门限和“合格/不合格”，最后输出总评。
默认门限在 `turntable_scan.yaml` 的 `turntable_axis_quality` 中：

```text
有效位姿数量             >= 10 帧
角度覆盖                 >= 90°
中心模型 RMS             <= 1.5 mm
中心模型最大值           <= 3.5 mm
旋转模型 RMS             <= 1.0°
旋转模型最大值           <= 2.0°
PnP 平均重投影误差       <= 2.0 px
```

任一项不合格时仍会保存 `turntable_axis.yaml` 供排查，但命令返回失败，
不能直接进入正式扫描。

如果中心模型误差较大，优先检查：

- 编码器角度方向是否与设定方向一致；
- 串口采样和图像帧时间是否稳定；
- ChArUco 板是否刚性、平整；
- 板原点是否离转轴太近；
- 相机或转台是否发生振动；
- 转台是否存在明显偏心和端面跳动。

转轴标定完成后，可以取下 ChArUco 板并安装被测物体，但不能移动相机、激光器或转台本体。

## 第二步：物体环绕扫描

将物体刚性固定在转台上。物体可以不与转轴完全同心，但必须保证旋转过程中：

- 不与相机、激光器碰撞；
- 始终处于激光平面和相机视野内；
- 转台和夹具本身的激光不会被保留为物体点；
- 一圈内不存在松动或滑移。

假设目标输出轴速度为 `1 deg/s`，目标每 `0.5°` 保存一帧：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/转台扫描/2_capture.ps1 `
  -MotorPort COM10 `
  -Cam 1 `
  -AngularVelocityDegS 1 `
  -StepDeg 0.5 `
  -MaxRotationDeg 360 `
  --width 800 `
  --height 600 `
  -Exposure -6 `
  -Gain 7 `
  -ClearOutput
```

正方向必须与转轴标定时一致。反向扫描时使用负值：

```powershell
-AngularVelocityDegS -1
```

扫描生成：

```text
data/scan/img_*.png
data/scan/angles.csv
data/scan/continuous_capture_report.json
```

## 第三步：五次手动画 ROI 并检查

执行：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/转台扫描/3_draw_check.ps1
```

程序会从整圈扫描中均匀选择五张关键帧，通常接近：

```text
0°、90°、180°、270°、360°
```

在每张关键帧中手动画一个矩形 ROI，只框住需要保留的物体激光区域。程序按 `angles.csv` 中的角度，在五个矩形之间线性插值，为其余所有帧生成对应 ROI。

操作：

```text
鼠标拖拽矩形：框住该角度下需要保留的物体激光
ENTER / SPACE：确认当前关键帧并进入下一张
R：重画当前矩形
S：跳过当前关键帧
Q / ESC：结束并保存已经确认的关键帧
```

输出：

```text
work/roi_keyframes.json
work/laser_check/check_*.png
```

逐张检查 `work/laser_check`：

- 绿色矩形应覆盖当前角度下的完整有效激光；
- 绿色矩形内尽量不要包含转台、夹具或背景激光；
- 红色激光中心应贴合激光亮核；
- 旋转到侧面和背面时也不能跳到反光或背景；
- 如果同一图像行出现多段独立激光，当前单分支中心提取不能同时保留所有分支。

每次重新采集都必须重新运行 `3_draw_check.ps1`。ROI JSON 与本批图片角度绑定，`2_capture.ps1 -ClearOutput` 会删除旧 ROI，避免误用上一批数据。

如果五次矩形的线性插值仍然包含背景激光，应在对应关键帧把矩形收紧。矩形 ROI 只能限制区域，不能像物体掩码一样描述不规则轮廓，因此采集时应尽量使用纯色背景并遮挡转台上的无关激光。

## 第四步：重建

检查通过后：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/转台扫描/4_rebuild.ps1
```

程序会：

```text
逐帧提取激光中心
→ 相机射线与激光平面求交
→ 得到当前相机坐标点
→ 读取该帧 angles.csv 角度
→ 绕 turntable_axis.yaml 中的轴反向旋转
→ 融合到第一帧公共坐标
→ 点云后处理和检查图
```

输出：

```text
output/cloud.ply
output/cloud_clean.ply
output/inspect_raw/
output/inspect_clean/
```

输出坐标仍以相机坐标为基础，并以扫描第一帧作为物体角度参考。它不是机械臂基座坐标或绝对转台坐标，但已经足够进行无 ICP 的整圈融合、尺寸和闭合验证。

## 第五步：精度验证

推荐先扫描已知尺寸的哑光球体、半球、圆柱或方块，不要直接用未知自由曲面判断精度。

例如标准半球直径为 `98.9 mm`：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/转台扫描/5_validate_hemisphere.ps1 `
  -DiameterMm 98.9
```

至少重复扫描三次。每次重建后先把点云复制到独立目录，再执行多次验证：

```powershell
$Clouds = @(
  "ceshi/转台扫描/output/repeat/1/cloud.ply",
  "ceshi/转台扫描/output/repeat/2/cloud.ply",
  "ceshi/转台扫描/output/repeat/3/cloud.ply"
)
$CloudList = $Clouds -join ";"

powershell -ExecutionPolicy Bypass `
  -File ceshi/转台扫描/5_validate_hemisphere.ps1 `
  -DiameterMm 98.9 `
  -InputList $CloudList `
  -ReportName "turntable_repeatability"
```

除球面拟合指标外，还必须专门检查：

1. `0°` 与 `360°` 附近是否出现双层、错缝或厚带；
2. 不使用 ICP 时，首尾重叠区域的距离；
3. 已知直径或边长的绝对偏差；
4. 三次扫描的尺寸极差；
5. 点云误差是否随角度周期性变化。

如果首尾错缝随转速增大而明显增大，优先怀疑：

- 图像时间与编码器回复时间不同步；
- 串口延迟波动；
- 转台速度波动；
- 连续运动造成模糊。

如果首尾闭合但整个点云偏心或尺寸随角度周期变化，优先怀疑：

- 转轴点或轴方向标定误差；
- 转台径向跳动、端面摆动；
- 激光平面深度系统误差；
- 物体相对转台发生滑移。

## 与未来机械臂扫描的关系

转台测试验证的是：

```text
连续曲线相对运动
+ 每帧位姿
+ 线激光局部重建
+ 公共坐标融合
```

机械臂到位后，角度和固定转轴模型会被每帧机械臂六自由度位姿替代：

```text
P_object = T_object_camera(i) · P_camera
```

机械臂还会新增：

- 相机到法兰的手眼标定；
- 机器人基座到物体的外参；
- 图像与机器人位姿时间同步；
- 机器人绝对定位和轨迹重复性；
- 末端振动和安装刚度。

因此转台扫描通过是机械臂环绕扫描的必要前期验证，但不能代替最终手眼标定和机器人轨迹精度验证。

## 约束

- 相机和激光器在转轴标定、扫描期间必须完全固定。
- 转台本体移动后必须重新标定转轴。
- 相机或激光安装变化后必须重新标定激光平面和转轴。
- 曝光、增益和激光中心参数必须与激光平面标定一致。
- 物体必须刚性固定在转台上。
- 每帧角度来自编码器时间插值，扫描时必须独占 HC32 串口。
- 正式重建使用五关键帧矩形 ROI，不再使用动态物体掩码。
- 每次重新采集后必须重新画五次 ROI。
- 首尾闭合验证不能先使用 ICP。
- 单视角线激光仍然存在遮挡和激光阴影；旋转可以改善覆盖，但不能恢复所有深凹区域。

## PLY 转 OBJ

重建后的主结果是点云 `ply`。若需要网格 `obj`，在测试包根目录执行已有脚本
`scripts/ply_to_obj.py`。

推荐先用清理后的点云：

```powershell
.\.venv\Scripts\python.exe scripts/ply_to_obj.py `
  --in ceshi/转台扫描/output/cloud_clean.ply `
  --out ceshi/转台扫描/output/mesh.obj `
  --method bpa `
  --no-roi
```

半球或自由曲面一般用 `bpa`。若只要更平滑的封闭感，可改成：

```powershell
.\.venv\Scripts\python.exe scripts/ply_to_obj.py `
  --in ceshi/转台扫描/output/cloud_clean.ply `
  --out ceshi/转台扫描/output/mesh_poisson.obj `
  --method poisson `
  --no-roi
```

说明：

- `--no-roi`：转台结果通常已在采集/重建阶段用关键帧 ROI 过滤，这里不再二次裁剪。
- `bpa`：适合表面片，默认优先用于半球检查。
- `poisson`：更平滑，但可能补洞或膨胀，尺寸检查仍以 `cloud_clean.ply` 为准。
- 尺寸与形状验证继续看点云，不要只用 `obj` 网格做直径判定。
