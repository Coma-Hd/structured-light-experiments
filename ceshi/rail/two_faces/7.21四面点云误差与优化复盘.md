# 7月21日四面点云误差与优化复盘

## 1. 本日目标

今天主要处理固定 ChArUco 板四次扫描路线中的以下问题：

1. 激光检查红点没有落在白色/白紫色激光核心。
2. 四面都能单独重建，但直接放入板坐标系后整体向外散开。
3. 重新标定和重建后效果明显改善，但四条棱仍有残余接缝。
4. 尝试四条共享棱全局平移闭环时，第一次点选结果被质量门限拒绝。

当前采用的是路线 B：

```text
物体固定在同一块 ChArUco 板上
相机和激光器保持刚性
四次扫描分别重建到同一板坐标系
优先直接合并
只有统一标定后仍有小平移接缝，才做受约束闭环
```

---

## 2. 最初现象：四面整体向外散开

四个面的逐帧 ChArUco 轨迹报告都能通过，但俯视合并结果存在明显间隙。四面并不是随机旋转，而是大致沿各自观察方向向外偏。

该现象说明：

```text
ChArUco 板坐标轴不是唯一问题
导轨方向也不是首要问题
更像四次重建共享了同一种深度系统误差
```

如果只是单独一个面被碰动，通常只会有一个面异常；四面共同外扩更符合激光中心或激光平面系统偏差。

---

## 3. 错误一：激光中心提取到了蓝色光晕

### 3.1 观察结果

在 `laser_check` 中，原来的红色提取点更偏向纯蓝色区域，没有落在肉眼看到的最亮白色或白紫色核心。

相机过曝后，真实激光核心不再是纯蓝色：

```text
中心：高亮、接近白色或白紫色
外围：饱和度较高的纯蓝色光晕
```

旧模式 `blue_minus_green` 主要强调蓝通道比绿通道高多少。白色核心的 B、G、R 都很高，通道差反而不一定最大；纯蓝光晕因此可能获得更高响应。

### 3.2 三维影响

激光中心存在约数像素系统偏差时，经过相机射线与激光平面求交，会形成数毫米甚至更大的深度偏差。

这种偏差会同时进入四个面的重建，因此最终表现为：

```text
单面形状大致合理
四面轨迹报告正常
四面合并后共同向外偏
```

### 3.3 优化

在 `src/laser_center.py` 中增加：

```yaml
score_mode: blue_weighted_intensity
```

其思想为：

```text
蓝色差异用于抑制非激光背景
亮度权重用于把中心拉向最亮白色/白紫色核心
```

同时将以下文件统一到相同模式：

```text
config.yaml
face1_scan.yaml
face2_scan.yaml
face3_scan.yaml
face4_scan.yaml
```

激光平面标定和实际扫描必须使用同一套中心提取参数。不能用旧响应标定激光平面，再用新响应重建物体。

---

## 4. 错误二：只修改提取模式但沿用旧激光平面

改变激光中心定义后，旧 `laser_plane.yaml` 对应的是旧像素中心，不能继续作为正式结果使用。

正确顺序是：

```text
修改并统一激光中心提取参数
重新采集或选用当前安装状态的激光平面标定图
重新标定激光平面
使用新激光平面重新重建四面
重新执行板坐标直接合并
```

如果相机、激光器和物体都没有移动，四面扫描图像可以重复使用，不必仅因为算法参数变化而重新采集；但四份点云必须重新计算。

如果相机和激光器之间的刚性关系发生变化，则必须在当前安装状态下重新标定激光平面，旧安装状态的数据不能混用。

---

## 5. 激光平面标定的进一步质量控制

为了避免板外反光或错误激光响应进入平面拟合，激光平面标定加入了以下限制：

```text
只保留 ChArUco 板凸包内部的激光中心
检查 ChArUco 重投影误差
检查平面拟合内点率
按文件名前缀筛选标定批次
```

这解决了早期标定图混批、板外激光点参与拟合以及平面质量无法自动拒绝的问题。

激光平面 RMS 越低越好。即使最终使用小范围平移闭环，也不能用闭环掩盖明显不合格的激光平面。

---

## 6. 错误三：Face4 重建时图像被并发采集清空

Face4 曾出现大量 OpenCV 提示：

```text
can't open/read file: check file path/integrity
RuntimeError: 没有任何有效帧
```

根因不是重建算法，而是采集和重建同时访问同一目录。另一个带 `-ClearOutput` 的采集进程正在清理或重写 Face4 图像，重建进程因此读取不到完整文件。

### 优化

`3_rebuild_face.ps1` 增加重建前检查：

```text
读取 continuous_capture_report.json
统计实际图像数量
统计 positions.csv 数据行数
检查三者是否一致
数据仍在采集或数量不完整时拒绝启动
```

后续必须遵守：

```text
同一 Face 不能同时采集和重建
确认采集进程结束后再运行 3_rebuild_face.ps1
使用 -ClearOutput 前确认没有需要保留的数据
```

## 7. 重新标定和重建后的结果

使用 `blue_weighted_intensity` 重新标定激光平面，并重新重建四面后，整体合并效果相比此前明显改善。

这证明白色/白紫色激光核心偏移确实是主要误差源之一。

但是四条棱仍存在不同程度的残余间隙。此时应区分：

```text
大范围共同外扩：优先检查激光中心和激光平面
单面随机错位：检查物体、板、相机或激光器是否被碰动
小范围稳定平移接缝：可以考虑受约束全局平移闭环
角度、尺度或上下错层：不能用平移闭环解决
```

## 8. 四条共享棱全局平移闭环

为处理统一重建后剩余的小平移接缝，新增：

```text
ceshi/rail/two_faces/7_pick_four_edges.ps1
ceshi/rail/two_faces/8_align_four_faces_loop.ps1
scripts/align_four_faces_translation_loop.py
```

### 8.1 约束关系

四条物理共享棱为：

```text
E12：Face1 / Face2
E23：Face2 / Face3
E34：Face3 / Face4
E41：Face4 / Face1
```

每条棱在两份点云中各点两个对应位置：

```text
同一物理棱靠近顶部的位置
同一物理棱靠近底部的位置
```

四条棱共 8 对对应点、16 次点击。

### 8.2 求解范围

求解器只调整：

```text
Face1～Face4 在 ChArUco 板 X/Y 平面内的平移
```

不会调整：

```text
旋转
尺度
板坐标 Z
单面内部形状
```

四个平移的平均值约束为零，避免整体模型任意漂移。四条边同时进入最小二乘求解，所以 Face4/Face1 的闭环误差不会被忽略。

### 8.3 质量门限

默认门限：

```text
任一面平移修正量 <= 25 mm
最终整体锚点 RMSE <= 5 mm
```

门限失败时仍会写出候选点云和报告，便于诊断，但该候选结果不能作为正式结果。

## 9. 错误四：第一次共享棱点选点到了相反端

第一次运行闭环的输出为：

```text
Face1 修正：47.986 mm
Face2 修正：58.432 mm
Face3 修正：51.059 mm
Face4 修正：51.188 mm

整体锚点 RMSE：62.968 mm
accepted：False
```

该结果被质量门限正确拒绝。

这不是求解器崩溃，也不是应该放宽 `MaxTranslationMm`。四个面需要约 50 mm 修正且最终仍有约 63 mm 残差，说明四组锚点在物理上互相矛盾。

### 9.1 四组锚点的实际结果

```text
Face1 / Face2：初始 RMSE 92.047 mm
Face2 / Face3：初始 RMSE 143.768 mm
Face3 / Face4：初始 RMSE 93.333 mm
Face4 / Face1：初始 RMSE 4.517 mm
```

Face4/Face1 已经很接近，说明这一组点到了正确共享棱。其余三组约为一个物体边长或对角方向的距离，说明点到了每个面的另一端。

### 9.2 锚点坐标证据

忽略高度 Z，只看板平面 X/Y，第一次点选大致为：

```text
Face1 / Face2：
  Face1 约 (217, 191) mm
  Face2 约 (234, 101) mm
  两者并非同一物理角棱

Face2 / Face3：
  Face2 约 (231, 189) mm
  Face3 约 (123, 94) mm
  两者位于物体相隔很远的两端

Face3 / Face4：
  Face3 约 (217, 93) mm
  Face4 约 (124, 102) mm
  两者并非同一物理角棱

Face4 / Face1：
  Face4 约 (124, 191) mm
  Face1 约 (127, 193) mm
  这一组基本正确
```

这些数据说明“先上后下”的顺序是正确的，Z 高度也基本对应；真正错误是选错了哪一条竖直棱。

### 9.3 为什么会误点

每一份面点云有左右两条竖直边。某个 Face 会在两组配对中各出现一次：

```text
Face2 第一次需要选择与 Face1 相邻的棱
Face2 第二次需要选择与 Face3 相邻的另一条棱
```

不能在 Face2 的两次窗口中都点同一侧，也不能根据屏幕左侧或右侧判断。点云视角可以自由旋转，屏幕方向不等于物体编号方向。

## 10. 正确点选逻辑

先在俯视关系中确认四个面的顺序：

```text
             Face1

      Face4          Face2

             Face3
```

然后选择：

```text
Face1 / Face2：
  Face1 靠 Face2 的端部
  Face2 靠 Face1 的端部

Face2 / Face3：
  Face2 靠 Face3 的端部
  Face3 靠 Face2 的端部

Face3 / Face4：
  Face3 靠 Face4 的端部
  Face4 靠 Face3 的端部

Face4 / Face1：
  Face4 靠 Face1 的端部
  Face1 靠 Face4 的端部
```

在每一端的竖直棱上：

```text
第一个点：靠近物体顶部
第二个点：靠近物体底部
```

“顶部/底部”是物体真实高度方向，不是 Open3D 窗口的屏幕上下。

如果棱的真实端点缺失，可以选择棱上的两个明显高度，但两份点云必须选择尽量相同的物理高度。

## 13. 今日结论

1. 四面共同外扩的主要原因之一是激光中心偏向蓝色光晕。
2. 改变中心提取方式后必须重新标定激光平面，并重新重建四面。
3. 重建与采集不能同时操作同一个 Face 目录。
4. 统一重建后的小平移接缝可以使用四边联合闭环，但不能修复旋转、尺度或非刚性形变。
5. 第一次闭环失败的直接原因是前三组共享棱选错，质量门限正确阻止了约 50 mm 的错误移动。
6. 当前不能使用第一次生成的 `loop_merged_candidate.ply` 作为正式结果。
7. 下一步应重新点选正确的四条物理共享棱，再根据报告判断闭环是否可接受。
