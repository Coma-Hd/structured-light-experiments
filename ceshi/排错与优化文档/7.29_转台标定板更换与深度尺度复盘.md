说明新板参数正确。最外圈纸边交界处没有红点是正常现象：ChArUco 只使用内部交点，不使用最外圈边界点。

## 4. 今日扫描与采集问题

### 4.1 采集被键盘提前停止

正式扫描设置了 `-MaxRotationDeg 360`，但有一次只采集到约：

```text
130 张
34.51°
stopped_by: keyboard
```

原因：编码器采集程序已自动启停，不需要再按空格。以下按键都会提前结束：

```text
SPACE / S / Q / ESC
```

### 4.2 角步距达不到 0.2°

目标：

```text
AngularVelocityDegS = 1
StepDeg = 0.2
```

实际常见情况：

```text
平均角步距约 0.27°
偶发跳到 0.36°～0.58°
警告：相机帧率不足
```

结论：在当前约 `1°/s` 和编码器采样条件下，稳定抽到 `0.2°` 偏紧。可选：

```text
保持 1°/s，StepDeg 改为 0.3
或保持 0.2°，速度降到约 0.6°/s
```

### 4.3 末尾图片缺失导致重建拦截

曾出现：

```text
report=304, png=294, angles=304
```

缺失为连续末尾：

```text
img_000294.png ～ img_000303.png
```

前缀完整，属于局部可用扫描。`4_rebuild.ps1` 已改为：末尾连续缺失时警告后按有效前缀重建；中间缺帧仍拒绝。

## 5. Laser Check 门禁位置

Laser Check 不单独写死在脚本中，门禁来自转台配置：

```text
ceshi/转台扫描/turntable_scan.yaml
  laser:
    score_threshold
    min_intensity
    blue_gate_threshold
    blue_gate_expand_px
    quality_filter.*
    dominant_track_filter.*
```

算法实现：

```text
ceshi/src/laser_center.py
```

改参数后需重跑：

```powershell
powershell -ExecutionPolicy Bypass -File ceshi/转台扫描/3_draw_check.ps1
```

若改动会影响中心位置（如 `score_mode`、门控、Steger），必须重新标定激光平面。

## 7. 深度尺度问题的含义

深度尺度误差通常来自：

1. 激光平面倾角标定偏差；
2. 扫描曝光/增益/蓝线参数与激光平面标定不一致；
3. 激光中心吸附到蓝晕一侧，而不是白色亮核；
4. 半球覆盖不足时球面拟合外推失真。

当前证据更支持：

```text
形态融合链路可用
→ 尺寸系统偏差主要在激光深度方向
```

下一步应优先：

```text
用正式扫描完全相同的 -6 / 7 和当前 laser 参数
重新标定激光平面
再扫同一半球验证直径是否回到接近 98.9 mm
```

## 9. 经验总结

1. 换标定板后，不要只改 YAML；必须清空旧标定图，并重做内参、激光平面、转轴。
2. ChArUco 最外圈无角点显示是正确行为；关键看 `corners` 是否达到内部最大角点数。
3. 编码器采集已自动启停，不要按空格，否则会提前结束。
4. `StepDeg` 过小会触发“相机帧率不足”；步距与转速要匹配。
5. 转轴机械不稳时，应把“形态是否圆”和“尺寸是否准”分开看。
6. 直径偏小/偏大互换出现时，优先查激光平面与深度尺度，而不是先怀疑编码器角度方向。
