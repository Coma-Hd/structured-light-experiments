## 2. 曲面扫描掩码问题

### 2.1 原问题

旧流程依靠多次手动画矩形 ROI。对于半球和其他曲面，物体在连续扫描图像中的位置会变化，固定矩形容易出现：

- ROI 包含过多标定板和背景；
- ROI 太小，切掉物体边缘激光；
- 不同关键帧矩形不一致；
- 每次采集后都要重复选择多个 ROI；
- 背景上的强蓝光可能抢走物体上的弱激光响应。

因此改为“选择一次物体，自动生成逐帧二值掩码”。

### 2.2 动态物体掩码流程

新增的主要文件：

```text
src/object_mask.py
scripts/draw_object_mask.py
```

处理流程：

```text
用户在参考帧框住物体
→ GrabCut 得到初始前景
→ 形态学开闭去除细小粘连
→ 中值滤波平滑轮廓
→ 只保留最大连通物体
→ 用户左键补选、右键擦除
→ 光流跟踪相邻帧特征
→ RANSAC 估计仿射运动
→ 每帧再次用 GrabCut 细化
→ 保存逐帧掩码和 manifest.json
```

配置入口：

```yaml
laser:
  object_mask:
    enabled: true
    dilate_px: 3
    morphology_px: 7
    smoothing_px: 9
    correction_brush_px: 8
    min_tracking_inlier_ratio: 0.30
    max_area_change_ratio: 0.35
```

### 2.3 为什么绿色轮廓比框选 ROI 大

矩形 ROI 只是 GrabCut 的初始化范围，不是最终轮廓。程序还会：

1. 在矩形内部判断前景和背景；
2. 平滑物体边缘；
3. 向外膨胀少量像素，避免切掉轮廓处的激光。

旧参数 `dilate_px=8` 会让轮廓明显向外扩大，因此调整为：

```text
dilate_px = 3
```

这样仍保留少量安全边距，但不容易扩进标定板。

### 2.4 掩码防误用

掩码清单现在记录原图的：

```text
文件名
图像尺寸
文件大小
修改时间
```

即使新一批图片继续使用相同文件名，只要图片被替换，程序也会拒绝旧掩码，防止上一批扫描的轮廓被静默用于新数据。

运行采集脚本并使用 `-ClearOutput` 时，也会同步清理旧掩码。

## 3. 激光中心断点优化

### 3.1 现象

早期 laser check 中，红点在半球表面存在明显断点。主要不是三维后处理问题，而是图像阶段的中心点已经被质量门限删除。

主要限制来自：

```text
max_width_px 过小
max_secondary_peak_ratio 过小
曲面反光导致激光变宽
木材纹理使主峰附近出现肩峰
```

### 3.2 参数调整

曲面和转台配置当前使用：

```yaml
quality_filter:
  enabled: true
  min_width_px: 1
  max_width_px: 70
  max_saturated_width_px: 4
  max_secondary_peak_ratio: 0.95
  secondary_exclusion_px: 12
  continuity_window: 5
  max_continuity_deviation_px: 4.0
```

调整含义：

- `max_width_px=70`：允许曲面上的宽蓝色光带继续进入 Steger 亚像素定位。
- `max_secondary_peak_ratio=0.95`：避免木纹和反光形成的次峰导致整段激光被删除。
- 饱和宽度和连续性门限仍然保留，用于拒绝严重过曝和突然跳变。

调整后物体表面的红点连续性明显提高。

## 4. 激光点“溢出”问题

### 4.1 现象与原因

放宽线宽和次峰门限后，部分图像中出现少量红点偏离主激光线。检查两张代表帧发现：

```text
首帧：
主激光中心 u ≈ 447～477 px
错误短分支 u ≈ 546 px

末帧：
主激光中心 u ≈ 401～447 px
错误短分支 u ≈ 326 px
```

这些点并不一定在绿色掩码外。部分错误响应位于物体掩码内部，因此仅靠缩小掩码或提高蓝色门限不能稳定删除。

### 4.2 新增主激光轨迹过滤

在 `src/laser_center.py` 中增加主轨迹过滤：

```text
按扫描方向排序中心点
→ 根据相邻行间距和横向跳变量分段
→ 选择最长连续段作为主激光锚点
→ 用二次多项式拟合平滑主轨迹
→ 删除偏离主轨迹超过4 px的短分支
→ 保留点继续使用原始亚像素中心
```

配置：

```yaml
dominant_track_filter:
  enabled: true
  max_order_gap_px: 3.0
  max_center_jump_px: 8.0
  min_anchor_points: 10
  polynomial_order: 2
  max_residual_px: 4.0
```

该过滤只删除明显偏离主线的响应，不会把保留点强制移动到拟合曲线上，因此不会人为把真实曲面压成规则形状。

代表帧验证结果：

```text
首帧溢出点：6 → 0
末帧溢出点：5 → 0
```

### 4.3 当前限制

该算法假设每张图像中需要保留一条主要、连续、平滑的激光分支。如果自由曲面造成同一图像行内出现多段相互独立的有效激光，当前算法可能只保留最长分支。

因此 laser check 仍是强制检查步骤，不能只看最终点云。

重新检查且不重新生成掩码：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/曲面/1_draw_check.ps1 `
  -ReuseMasks
```

## 5. 激光平面标定识别优化

为降低错误像素对激光平面标定的影响，标定流程形成了多级过滤：

1. 使用绿色通道检测 ChArUco，减小蓝色激光对角点的干扰。
2. 在中心提取前把响应限制在 ChArUco 凸包内。
3. 删除距激光中心过近、可能被蓝线覆盖的 ChArUco 角点。
4. 对每帧中心执行响应强度和二维主条带过滤。
5. 每帧在三维中拟合板面与激光面的交线。
6. 删除偏离该物理直线过大的局部中心。
7. 每帧最多均匀保留120个点，避免长激光帧支配结果。
8. 跨帧先寻找属于同一激光平面的整帧共识，再执行最终平面拟合。

核心判断原则没有改变：

```text
低内点率不能只靠放宽 min_inlier_ratio 强行通过。
激光中心参数改变后，激光平面必须使用同一参数重新标定。
正式扫描的曝光、增益、分辨率和激光参数必须与标定一致。
```

当前统一采集参数：

```text
Resolution = 800 × 600
Exposure = -4
Gain = 10
```

## 8. 转台扫描的几何原理

相机与线激光固定，物体绕转台轴旋转。每帧激光点仍先通过：

```text
像素
→ 相机内参反投影射线
→ 射线与激光平面求交
→ 当前相机坐标 P_current
```

设转轴上一点为 `C`，单位方向为 `n`，当前帧相对参考帧转角为 `θ`：

```text
P_current = C + R(n, θ) · (P_reference - C)
```

为了把当前帧恢复到第一帧公共坐标，重建时执行：

```text
P_reference = C + R(n, -θ) · (P_current - C)
```

因此整圈融合不依赖 ICP，而依赖：

```text
相机内参
激光平面
转轴点和轴方向
每帧真实转角
物体与转台的刚性连接
```

## 9. 转台旋转轴标定

### 9.1 标定方法

将 ChArUco 板刚性安装在转台上，并让板原点离转轴有一定距离。板旋转时，程序从每帧估计：

```text
R_board_to_camera
t_board_to_camera
```

轴方向通过不同角度间的相对旋转估计：

```text
R_relative =
R_current · R_reference^T
```

多个相对旋转的 Rodrigues 旋转向量给出转轴方向候选，统一正负方向后求平均。

轴上一点通过板原点的圆周运动模型求解：

```text
O_current =
C + R(n, θ) · (O_reference - C)
```

程序用全部有效帧做最小二乘，并增加约束选择距离相机光心最近的轴上一点，解决轴线上点沿轴方向不唯一的问题。

### 9.2 输出指标

`turntable_axis.yaml` 包含：

```text
axis_point_m
axis_direction
reference_image
reference_angle_deg
board_origin_radius_m
valid_pose_frames
angle_span_deg
center_model_rms_m
center_model_max_m
rotation_model_rms_deg
rotation_model_max_deg
mean_reprojection_error_px
```

这些指标分别检查：

- ChArUco检测是否稳定；
- 标定角度覆盖是否足够；
- 板原点是否符合绕固定轴画圆；
- 板姿态旋转是否符合单一固定转轴；
- 转台是否存在跳动、打滑或时间角度误差。

## 10. 转台角度采集

当前转台尚未由程序直接读取编码器，因此角度按稳定匀速和采集时间估算：

```text
angle_deg =
start_deg
+ (当前帧时间 - 第一张保存帧时间)
× angular_velocity_deg_s
```

程序按目标角度步距换算保存周期：

```text
save_interval_s =
StepDeg / abs(AngularVelocityDegS)
```

每次采集生成：

```text
img_*.png
angles.csv
continuous_capture_report.json
```

报告记录：

- 假定角速度；
- 请求角步距；
- 保存周期；
- 实际保存张数；
- 实际记录角度跨度；
- 相邻帧角度增量范围；
- 曝光和增益；
- 停止原因；
- 时间角度公式和风险提示。

### 10.1 操作要求

必须：

1. 先启动转台；
2. 等待转速稳定；
3. 在计划起始位置按空格开始采集；
4. 采集完成后再减速；
5. 正反转时同步修改角速度正负号；
6. 使用实测角速度，而不是直接相信电机名义速度；
7. 扫描期间避免电脑高负载。

当前时间推算角度适合流程验证，但不能等同于编码器实测角度。若要提高计量能力，应优先把每帧编码器角度直接写入 `angles.csv`。

## 12. 为什么转台流程不先使用 ICP

转台流程的目标是验证标定和位姿能否直接产生正确的公共坐标：

```text
每帧真实三维点
+ 每帧真实角度
+ 正确转轴
= 首尾直接闭合
```

如果先使用 ICP：

- 首尾错缝可能被强行拉合；
- 转轴位置误差可能被掩盖；
- 角速度或时间同步误差可能被掩盖；
- 尺寸错误不一定被修复；
- 对称球体、圆柱体上容易出现伪配准。

因此首轮验收必须查看不使用 ICP 的：

```text
0°/360°首尾错缝
重叠区域双向距离
已知直径误差
多次扫描尺寸极差
随角度变化的周期性误差
```

## 13. 与未来机械臂扫描的关系

转台扫描验证的是固定一维旋转模型：

```text
连续相对运动
+ 每帧位姿
+ 线激光三角测量
+ 公共坐标融合
```

机械臂扫描会把固定转轴和单一角度替换为每帧六自由度位姿：

```text
P_object =
T_object_camera(i) · P_camera
```

机械臂还需要：

- 相机/激光扫描头到机械臂法兰的手眼标定；
- 机器人基座到被测物体的外参；
- 图像与机械臂位姿时间同步；
- 机械臂绝对定位和重复定位精度；
- 末端安装刚度与振动控制。

因此转台测试是机械臂环绕扫描的重要前置验证，但不能替代手眼标定。

## 15. 下一步真实转台验收顺序

### 优先级一：测量真实角速度

不要直接使用控制器显示值。应让转台连续旋转多圈，用秒表或编码器测量总时间：

```text
实际角速度 =
总旋转角度 / 总时间
```

多圈平均可以减小人工计时误差。

### 优先级二：标定并检查固定转轴模型

重点记录：

```text
有效位姿数量
角度覆盖
中心模型 RMS / 最大值
旋转模型 RMS / 最大值
平均重投影误差
```

如果中心模型误差很大，优先检查板刚性、角速度、加减速段、转台跳动和相机振动，不要直接进入物体扫描。

### 优先级三：先扫描标准件

推荐顺序：

```text
哑光标准半球
→ 圆柱
→ 方块
→ 普通自由曲面
→ 反光复杂物体
```

### 优先级四：检查首尾闭合

首先观察：

- 0°与360°是否形成双层；
- 双层厚度是否随转速增大；
- 错缝是否随角度逐渐累积；
- 尺寸误差是否呈周期性。

## 16. 本次结论

1. 曲面扫描已从多次手动矩形 ROI 升级为一次选择、逐帧跟踪的动态物体掩码。
2. 掩码轮廓过大主要来自 GrabCut 边界与膨胀参数，当前已将膨胀减小到3 px，并增加清理和人工修正。
3. 曲面激光断点主要来自线宽和次峰质量门限过严，当前已针对宽激光和材质肩峰放宽。
4. 放宽质量门限后出现的短小溢出分支，已通过主激光轨迹过滤删除；代表帧溢出点均降为0。
5. 已建立固定的单次半球尺寸分析和多次扫描重复性报告流程。
6. 已新增完整转台扫描工作区，支持转轴标定、时间角度采集、动态掩码、无ICP旋转融合和标准件验证。
7. 转台几何公式和合成数据测试已经通过，但真实转台的轴标定精度、角度同步和360°首尾闭合仍需实测。
8. 当前转台最大风险不是点云滤波，而是“时间估算角度”与真实转角不一致。后续若能接入编码器，应优先使用逐帧实测角度。
