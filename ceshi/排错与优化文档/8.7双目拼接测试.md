# 8.7 复盘：Gemini 305 双目多视角拍摄与点云拼接测试

## 1. 今日目标

在 Windows 本机用奥比中光 **Gemini 305** 做双目多视角采集，验证：

1. 能否稳定打开左右 IR/彩色流并实时预览；

3. 多视角点云链式配准融合后，整体形状是否可用；
4. 跑通「采集 → 处理 → 落盘」流程（处理完不弹结果窗，结果进文件夹）。

## 2. 方案结论：融合可用，深度与杂点仍是短板

| 项目 | 今日结论 |
|------|----------|
| 双目取流 / 实时预览 | **可用**（Gemini 305 上优先 LEFT/RIGHT IR；单开 RGB 易卡帧） |
| 单视角立体深度（SGBM） | **偏差大 / 不稳定**（短基线 + IR 噪声） |
| 点云杂点 | **仍明显**（视差错误、远距噪声、未充分滤波） |
| 多视角融合对齐 | **看起来还可以**（相邻视角链式 Kabsch + ICP） |
| 结果交付方式 | **只写文件夹**，不弹匹配/点云结果窗；拍摄时保留实时预览 |

一句话：

> **位姿拼接链路已经能把多视角叠到一起；当前主要矛盾不在融合，而在单帧深度质量与杂点。**

## 4. 技术链路（今日实现）

```text
Gemini 305 左右流（优先 IR stereo）
  → 实时预览
  → 按 SPACE 存 N 组 left/right
  → 每组：StereoSGBM 视差 → 深度 Z = bf / d
  → 反投影生成 view_i.ply
  → 相邻视角：左图特征匹配 + Fundamental 过滤
  → 有深度的 3D 对应 → Kabsch RANSAC 粗配准
  → 多尺度 Point-to-Plane ICP 精配准
  → 位姿链式累乘到 view1 坐标系
  → voxel + 统计滤波 → merged.ply
```

关键参数（默认 / 经验）：

| 参数 | 默认 | 说明 |
|------|------|------|
| `baseline` | 0.018 m | Gemini 305 约 18 mm |
| `fx/fy` | SDK 或 `0.9*max(W,H)` | 今日部分数据落在近似焦距 |
| `min_z / max_z` | 0.15 / 3.0 m | 深度截断 |
| `voxel` | 0.006 m | 下采样 |
| 配准 | 相邻链：2→1，3→2→1 … | 避免大视角跨度直接配准失败 |

输出文件（单次）：

```text
camera.json
view{i}_left.png / view{i}_right.png
view{i}_disparity.png / view{i}_depth.npy / view{i}.ply
match_{i}_{i+1}.png
transforms.json
summary.json
merged.ply          ← 主结果
```

## 5. 配准改进（相对首版）

首版问题：直接用稀疏 3D 对应做 Open3D correspondence RANSAC，1↔3 跨度大时易偏，融合发虚。

今日加强后：

1. 2D 匹配加 Fundamental RANSAC；  
2. 关键点深度取邻域中值，并做相对深度一致性门控；  
3. 自写 Kabsch RANSAC 粗解；  
4. 多尺度 ICP 精修；  
5. **相邻链式**配准，再对后续视角做 polish。

早期三视角重跑时，粗配准中位误差约 **2 cm**，ICP rmse 约 **1.4 cm**，肉眼融合「还可以」。  
十视角沿用同一套链路；视角越多，链式误差可能累积，需靠拍摄重叠与后续全局优化压住。

## 6. 当前主要问题

### 6.1 深度有问题（主因）

1. **基线太短**（≈18 mm）：同视差误差放大到深度上很大，远距离更差；  
2. **IR + SGBM**：激光散斑/纹理不足时视差易错；  
3. **内参/基线未严格标定**：部分 run 使用近似 `fx`，尺度与深度都会偏；  
4. 未做完整立体校正（rectify）时，SGBM 假设不够成立。

表现：表面起伏不准、远景糊成一片、局部深度跳变。

### 6.2 杂点仍多

1. 错误视差点反投影成飞点；  
2. 边缘 / 遮挡 / 高反光区域；  
3. 当前仅 voxel + 统计滤波，对结构性飞点不够狠；  
4. 多视角叠合后，错误深度会被「焊」进融合云。

### 6.3 融合相对可接受的原因

- 相邻拍摄重叠较大时，特征+ICP 能把「块」对齐；  
- 人眼对整体轮廓对齐更敏感，对局部毫米级深度误差不那么敏感；  
- 因此：**看起来能拼上 ≠ 深度已经准**。

---

## 7. 拍摄建议（在现有硬件上）

1. 绕物体小步转，相邻视角重叠尽量 **>60%**；  
2. 工作距离优先约 **0.3–1.5 m**（太远深度崩）；  
3. 避免大面积白墙、强反光；尽量有纹理；  
4. 十次拍摄尽量覆盖一圈，不要两张之间转角过大；  
5. 拍满后看 `merged.ply` 与各 `view{i}_disparity.png`，先排深度再谈精度。

## 8. 与结构光主线的关系

| | 结构光主线（ceshi） | 今日双目测试 |
|--|-------------------|--------------|
| 传感器 | 线激光 + 单目 | Gemini 305 双目 IR |
| 单帧 3D | 激光平面求交 | SGBM 稠密深度 |
| 多帧对齐 | 板坐标 / 编码器 / 臂 | 视觉特征 + ICP |
| 今日价值 | 对照：无板时纯视觉拼接能力 | 快速验证多视角融合流程 |

结论：双目可作为「无标定板、手持换视角」的补充试验；**若要精度，仍应回到结构光 + 板/编码器几何**，或给双目补严格标定与更好的深度前端。

## 9. 下一步（建议优先级）

1. **深度前端**  
   - 跑 `export_intrinsics.py`，用真实 fx/fy/cx/cy；确认 baseline；  
   - 尝试 SDK 硬件深度流（若 Gemini 305 稳定出 depth）替代纯 SGBM；  
   - 或加立体校正后再 SGBM。  

2. **去杂点**  
   - 加深左右一致性 / 置信度掩膜；  
   - 按半径滤波、法向一致、深度梯度剔飞点；  
   - 融合前按置信度加权，而不是等权叠。  

3. **融合**  
   - 十视角后做一次 pose-graph / 全局 ICP，减轻链式漂移；  
   - 保存并可视化每段 `fitness/rmse`，失败段自动提示重拍。  

4. **流程**  
   - 需要时把输出目录规范进 `ceshi/` 对照实验区；  
   - 与同场景结构光结果做并排对比（轮廓 / 厚度 / 飞点）。
