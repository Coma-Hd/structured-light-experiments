## 2. 四面点云问题的重新判断

### 2.1 最初假设

四个单面分别看起来较平整，但在同一 ChArUco 板坐标系下直接合并时仍存在明显分离。最初怀疑：

```text
相机坐标到板坐标的变换方向错误
R、t 使用了错误的逆变换
四次扫描使用了不一致的板坐标
激光平面标定存在系统误差
```



### 2.2 坐标变换检查

重新检查的核心公式为：

```text
P_camera = R · P_board + t
P_board  = Rᵀ · (P_camera - t)
C_board  = -Rᵀ · t
```

程序行向量形式：

```text
(P_camera - t) @ R
```

与列向量公式等价。数值往返测试误差约为 `1e-16 m`，没有发现转置、逆变换方向或米/毫米单位错误。

因此，当前证据不支持“坐标变换代码错误”是主要原因。

### 2.3 当前四面数据的几何特征

自动分析发现：

- 四个主平面本身拟合 RMS 约 `0.67～0.82 mm`。
- 相邻面夹角约 `85.4～88.3°`，整体方向基本合理。
- 对面平行误差较小。
- 四条接缝 XY 间隙约 `10.95～16.37 mm`。
- 接缝沿高度方向较稳定，MAD 约 `0.25～0.74 mm`。
- 四个面表现为近似沿各自观察方向共同向外扩张。

最小二乘估计的各面径向外扩量约为：

```text
Face1： 7.92 mm
Face2：11.78 mm
Face3： 7.15 mm
Face4： 8.73 mm
```

这种“共同向外”的模式更符合激光三角测量深度系统误差，而不是某一个面偶然移动。

### 2.4 当前数据缺少真正重叠

相邻点云在 `25 mm` 距离内的双向覆盖率仅约：

```text
Face1–Face2：12.16%
Face2–Face3：14.03%
Face3–Face4：16.19%
Face4–Face1：16.61%
```

在 `10 mm` 内几乎没有可靠对应。四份点云实际上是四片互相垂直、在理论棱边附近接触的单面数据，而不是重复测量了同一块实体表面。

### 2.5 为什么普通 ICP 不可用

对当前数据放宽 ICP 搜索距离后，算法可能得到表面上较高的 fitness，但同时产生：

```text
旋转约 87～94°
平移数百毫米
```

原因是大面积平面具有强对称性。无约束 ICP 会把一整片主面错误地吸附到另一片垂直主面上，看起来闭合，实际物理对应关系完全错误。

FPFH/RANSAC 同样产生约 `93～177°` 旋转和 `275～451 mm` 平移，说明无重叠平面没有足够独特的三维特征。

### 2.6 自动工具的实验实现

新增了以下实验工具：

```text
scripts/analyze_four_face_alignment.py
scripts/auto_align_four_faces.py
scripts/complete_cuboid_from_planes.py
src/four_face_alignment.py
tests/test_four_face_alignment.py
```

对应入口：

```text
9_analyze_four_faces.ps1
10_auto_align_four_faces.ps1
11_complete_cuboid.ps1
```

功能分别为：

1. 自动量化平面、角度、理论交线、边缘覆盖、相邻覆盖率和位姿模式差异。
2. 在 ChArUco 强初值下，只匹配法向一致的真实共享条带，并进行小范围四面联合 SE(3) 优化。
3. 对确认属于方木块的工件，生成明确标记为 synthetic 的闭合侧面和网格。

当前旧数据由于没有法向一致的真实重叠条带，被自动配准正确安全拒绝：

```text
Face1–Face2：0 个最终对应
Face2–Face3：0 个最终对应
Face3–Face4：1 个最终对应
Face4–Face1：0 个最终对应
accepted = false
exit code = 2
```



### 2.7 路线调整

虽然重新采集“主面 + 下一面连续条带”能够为 ICP 提供真实对应，但 ICP 只能修正小范围刚体位姿误差，不能修正激光平面造成的错误深度和错误尺寸。

因此，面向计量结果的正式方向调整为：

```text
先保证相机内参、激光平面和位姿的绝对准确
每帧直接转换到同一板坐标或机器人世界坐标
直接融合，不用 ICP 改变点云位姿
重叠区域只用于误差检查和拒绝，不用于掩盖标定误差
```

方木块平面/棱边约束只能用于诊断或外观补全，不能作为真实测量数据。

## 3. 独立曲面扫描工作区



### 3.1 建立原因

原项目中扫描图片、positions.csv、ROI、输出点云和标定结果分散在：

```text
data/
output/
ceshi/rail/scan/
ceshi/rail/two_faces/work/
ceshi/rail/two_faces/output/
```

这会导致：

- 容易引用错误批次。
- 容易把四面扫描 ROI 用到曲面扫描。
- 标定 YAML 和扫描参数难以一一对应。
- 复制到其他电脑后路径容易失效。

因此建立独立目录：

```text
ceshi/曲面/
  curve_scan.yaml
  0_capture.ps1
  1_draw_check.ps1
  2_rebuild.ps1
  calibration/
    camera_intrinsic.yaml
    laser_plane.yaml
  data/
    calibration/
      intrinsic/
      laser_plane/
    scan/
  work/
    roi_keyframes.json
    laser_check/
  output/
```

曲面采集图片、位置记录、ROI、标定副本和输出点云均保存在该目录下。

### 3.2 曲面配置原则

自由曲面不能使用平面专用清理逻辑，因此配置为：

```yaml
pipeline:
  extract_largest_plane: false
  finish_mesh: false

postprocess:
  voxel_size: 0.0002
  mesh_method: "none"
  two_plane_cleanup:
    enabled: false
```

首次扫描时关闭三维自动 ROI，避免真实凸起、凹陷和边缘被自动裁掉：

```yaml
roi:
  enabled: false
```

物体、板面和背景的分离优先通过关键帧图像 ROI 完成。

### 3.3 当前 Steger 的限制

当前 Steger 实现按 `scan_axis: row` 工作，每个图像行只保留全局最强的一个响应：

```text
每行 argmax
→ Steger 亚像素细化
→ 一个中心点
```

这适合连续、单值的凸曲面。对于深凹槽、孔洞或同一行出现多段激光的雕塑表面，可能漏掉其他分支。

如果出现多段激光，后续应升级为：

```text
多连通分支候选
每个分支内部做 Steger 亚像素定位
结合相邻行和相邻帧连续性选择物理激光线
```

在升级中心定义后，必须用相同算法重新标定激光平面。

## 4. Windows PowerShell 中文路径乱码



### 4.1 第一次故障

运行：

```powershell
powershell -ExecutionPolicy Bypass `
  -File ceshi/曲面/0_capture.ps1
```

Python 实际收到：

```text
ceshi/鏇查潰/curve_scan.yaml
```

并报错：

```text
FileNotFoundError: 找不到配置文件
```



### 4.2 根本原因

Windows PowerShell 5.1 对无 BOM UTF-8 `.ps1` 文件可能按本地 ANSI 编码解析。脚本源码中的中文“曲面”被错误解码为“鏇查潰”。

### 4.3 修复方式

三个曲面入口不再在 PowerShell 源码中硬编码中文路径，而是使用：

```powershell
$CurveRoot = $PSScriptRoot
$Config = Join-Path $CurveRoot "curve_scan.yaml"
$ScanDir = Join-Path $CurveRoot "data\scan"
```

这样 `$PSScriptRoot` 由 PowerShell 根据真实脚本位置提供，不需要重新解码中文路径字符串。

### 4.4 便携包 install.ps1 的同类问题

`install.ps1` 原来在 Required 列表中直接包含：

```text
ceshi\曲面\curve_scan.yaml
ceshi\曲面\calibration\camera_intrinsic.yaml
ceshi\曲面\calibration\laser_plane.yaml
```

PowerShell 5.1 同样把它们解码成乱码，安装完成后误报文件缺失。

修复为从文件系统自动搜索：

```text
在工作流目录递归查找唯一的 curve_scan.yaml
以该文件的父目录作为 CurveRoot
再用 ASCII 子路径检查 calibration、data、work 和 output
```

这同时提高了曲面目录被移动后的可移植性。

## 6. 曲面首次扫描的大量杂点



### 6.1 现象

第一次扫描金属曲面后，虽然执行了体素降采样和 SOR，点云中仍存在：

- 长条状假点。
- 沿扫描方向连续的尖刺。
- 板面和背景附近的密集错误结构。
- 与主体相连、不能被 DBSCAN 简单分开的伪表面。

后处理前后：

```text
raw：   45,515 点
clean：43,285 点
```

SOR 只删除约 2,230 点，主要伪结构仍保留。

### 6.2 为什么聚类和 SOR 无法清理

这些点不是随机孤立噪声，而是镜面反射形成的连续假激光线。它们具有：

```text
局部密度较高
沿扫描方向连续
部分与真实曲面连接
邻域统计与真实点接近
```

所以：

- SOR 会认为它们具有正常邻域。
- DBSCAN 会把它们并入主簇。
- 继续提高滤波强度会先损伤真实边缘。



### 6.3 原图证据

原始图像中的金属表面存在：

- 大面积紫色/蓝色光斑。
- 激光中心明显变宽。
- 镜面高光与真实激光核心混合。
- 激光同时落在物体、板面、地毯和背景纸箱上。

当时参数：

```text
Exposure = -3
Gain = 20
```

Gain 过高，显著放大了蓝色噪声和金属反射。

### 6.4 L 键预览的含义

`L` 键原来显示的是整幅 `blue_gated_intensity` 响应热图：

```python
score = blue_laser_score(...)
heat = cv2.applyColorMap(score)
preview = 0.5 * frame + 0.5 * heat
```

它不是最终 Steger 中心点，也没有只显示阈值以上像素。因此画面会比最终提取结果更“花”。

但白板和金属表面出现大面积高响应仍然说明：

```text
blue_gate_threshold = 5 较宽松
白色区域只要略微偏蓝就会通过门控
金属镜面反射与真实激光具有相同光谱，颜色门控无法区分
```



### 6.5 参数优化

实测后确定：

```text
Gain = 1
Exposure = -5
```

能够明显减小光晕和饱和反射。

已同步修改：

```text
scripts/capture.py
scripts/continuous_rail_capture.py
ceshi/曲面/0_capture.ps1
```

默认值现在统一为：

```text
Exposure = -5
Gain = 1
```

普通采集程序的 `L` 预览也补充传入 `blue_gate_threshold`，避免预览与实际配置使用不同门限。

### 6.6 根本改进建议

对于反光金属，最有效的处理顺序为：

1. 使用可清洗三维扫描显像剂或哑光喷剂。
2. 调低 Gain 和 Exposure，使激光核心宽约 `2～4 px`。
3. 固定最终参数后重新标定激光平面。
4. 增加逐帧激光线连续性约束。
5. 检测光斑宽度和饱和面积，过宽时拒绝该段。
6. 相邻帧跟踪同一激光分支。
7. 最后再做三维 ROI、SOR 和小簇清理。

不能依赖点云聚类修复已经错误三角测量出来的连续伪表面。

## 7. 曝光、增益与激光平面必须配套



### 7.1 为什么修改相机参数后要重新标定

曝光和增益不改变理想相机几何，但会改变：

- 激光核是否饱和。
- 光斑宽度。
- Steger 所看到的亮度剖面。
- 金属、木材和白板上的中心偏移。
- 哪些像素能通过门限。

激光平面标定使用的是“提取出的激光中心像素”。中心定义改变后，即使相机和激光器完全没有移动，拟合平面也可能发生角度变化。

历史经验已经证明：激光平面法向只变化约 `0.15～0.23°`，代表性射线上的深度就可能变化约 `10 mm`。

因此正式约束为：

```text
内参、激光平面标定、正式扫描必须保持相同分辨率
激光平面标定和正式扫描必须保持相同 Exposure/Gain
激光平面标定和正式扫描必须保持相同 score_mode/门限/Steger 参数
改变任一激光中心参数后，旧 laser_plane.yaml 作废
```



### 7.2 当前旧激光平面

曲面目录此前复制的激光平面为：

```text
fit_rms_m = 0.000731394
num_points = 1877
```

该文件来自之前的拍摄设置，不是 Gain=1、Exposure=-5 下重新标定的结果。

因此，使用新曝光/增益扫描但继续使用旧激光平面，只能用于观察重复性，不能用于声明绝对尺寸精度。

## 8. 内参与激光平面标定流程补齐



### 8.1 内参采集

统一命令：

```powershell
.\.venv\Scripts\python.exe scripts/capture.py `

  --out ceshi/曲面/data/calibration/intrinsic `
  --mode shot `
  --cam 0 `

  --height 600 `
```

建议拍摄 `20～30` 张：

- 中心、四角均有覆盖。
- 包含远近变化。
- 包含绕两个方向的倾角。
- 避免所有图片姿态接近。
- 避免模糊和反光。

标定：

```powershell
.\.venv\Scripts\python.exe scripts/1_calibrate_intrinsic.py `
  --config ceshi/曲面/curve_scan.yaml `
  --images ceshi/曲面/data/calibration/intrinsic `
  --out ceshi/曲面/calibration/camera_intrinsic.yaml
```



### 8.2 激光平面采集

保持相机、镜头、激光器刚性不变：

```powershell
.\.venv\Scripts\python.exe scripts/capture.py `
  --config ceshi/曲面/curve_scan.yaml `
  --out ceshi/曲面/data/calibration/laser_plane `
  --mode shot `
  --cam 0 `
  --width 800 `
  --height 600 `
  --exposure -5 `
  --gain 1
```

采集要求：

- 至少 `15～20` 个有效板姿态。
- 覆盖正式扫描工作距离。
- 激光只使用落在实体 ChArUco 板内的部分。
- 每次移动标定板后等待完全静止。
- 不混入旧参数、旧安装或其他批次图片。

标定：

```powershell
.\.venv\Scripts\python.exe scripts/2_calibrate_laser_plane.py `
  --config ceshi/曲面/curve_scan.yaml `
  --images ceshi/曲面/data/calibration/laser_plane `
  --intrinsic ceshi/曲面/calibration/camera_intrinsic.yaml `
  --out ceshi/曲面/calibration/laser_plane.yaml
```



### 8.3 不能只看 RANSAC RMS

低 RANSAC RMS 只表示被选中的内点接近某个拟合平面，不代表绝对深度正确。

必须补充留出验证：

```text
保留若干没有参与拟合的板姿态
用新激光平面重建这些板面激光点
转换到各自板坐标
检查 Z=0 的平均偏差、RMS、P95 和最大值
```

建议验收目标：

```text
平均深度偏差：尽量 < 0.5 mm
RMS：          尽量 < 0.5 mm
P95：          尽量 < 1.0 mm
```

## 12. 半球结果的原因排序



### 12.1 第一嫌疑：旧激光平面

Gain/Exposure 已改为 `1/-5`，但扫描仍使用以前拍摄参数下的激光平面。

曝光改变会改变激光亮核的位置和宽度，导致：

```text
像素中心偏移
射线方向偏移
射线与激光平面的交点深度偏移
球面曲率和直径发生系统变化
```

三次都偏小约 `5.6 mm`，与稳定激光深度偏差高度一致。

### 12.2 第二嫌疑：无显像剂的材质响应

标准半球没有喷显像剂。若表面存在高光或颜色不均，激光亮度剖面可能相对标定板发生材质相关偏移。

这会表现为：

- 曲面不同区域残差不同。
- 边缘或掠射区域误差增大。
- 球面拟合半径发生系统偏移。



### 12.3 第三嫌疑：导轨/ChArUco 轨迹

三次导轨中心拟合 RMS 约：

```text
1.299～1.349 mm
```

最大中心残差约：

```text
3.58～3.89 mm
```

轨迹误差会增加局部层间错位和球面残差，但三次拟合直径高度一致，说明它不是 `-5.65 mm` 绝对尺寸偏差的唯一原因。

### 12.4 不应使用的“修复”

不能通过以下方式把结果强行变成 98.86 mm：

```text
ICP
整体缩放点云
强制球面半径
后处理投影到理论球面
手工拖动或拉伸
```

这些方法只会掩盖标定误差，不能提高真实检测精度。

## 16. 7月24日下午补充：激光线宽质量门控

进一步检查激光平面标定后，确认“减少正确点总数”不是优化目标。当前 Steger 每行/列最多输出一个亚像素中心，`1877` 个平面内点本身并不过多；真正需要拒绝的是粗线、饱和线、双峰和不连续中心。

本次在 `src/laser_center.py` 中增加可配置质量过滤：

```yaml
quality_filter:
  enabled: true
  width_level: 0.5
  min_width_px: 1
  max_width_px: 10
  saturation_threshold: 250
  max_saturated_width_px: 4
  max_secondary_peak_ratio: 0.80
  secondary_exclusion_px: 12
  continuity_window: 5
  max_continuity_deviation_px: 4.0
```

各门限含义：

1. `width_level`：以主峰一定比例计算连续线宽；当前使用半高宽。
2. `min/max_width_px`：拒绝过窄噪点和过宽反光光斑。
3. `max_saturated_width_px`：拒绝连续大面积饱和区域。
4. `max_secondary_peak_ratio`：若同一行/列存在接近主峰的第二峰，拒绝该中心。
5. `continuity_window`：在局部连续扫描线内检查中心轨迹。
6. `max_continuity_deviation_px`：拒绝相对局部中位数突然跳变的孤立中心。

过滤只删除不合格中心，不平滑或移动保留下来的亚像素坐标。

激光平面标定还增加两项处理：

```text
先用 ChArUco 角点凸包掩膜响应，再执行逐行/列 argmax
每个板姿态最多均匀保留 120 个高质量点
```

第一项修复了以下旧问题：

```text
同一图像行中板外激光更亮
→ 旧算法先选中板外 argmax
→ 后续凸包过滤将它删除
→ 板内真实激光没有机会成为候选
```

现在板外响应在中心提取前已清零。

第二项不是单纯减少点数，而是让每个标定板姿态近似等权，避免“可见激光更长”的姿态对最终平面产生过大影响。

新增单元测试覆盖：

```text
宽峰拒绝
双峰拒绝
孤立中心跳变拒绝
板掩膜必须在逐行 argmax 前生效
```

任何质量门限改变后，旧激光平面必须作废；激光平面标定和正式扫描必须使用同一份 `curve_scan.yaml`。

## 17. 7月24日下午后续：激光平面低内点率的二次诊断

### 17.1 现象

重新采集激光平面图片后，标定仍然失败：


```text
阈值 1.0 mm：内点率 26.2%，RMS 0.511 mm
阈值 1.5 mm：内点率 33.7%，RMS 0.784 mm
阈值 2.0 mm：内点率 40.3%，RMS 1.014 mm
阈值 3.0 mm：内点率 50.2%，RMS 1.436 mm
阈值 5.0 mm：内点率 65.1%，RMS 2.447 mm
```

只有将阈值放宽到 `5 mm` 才能越过 `65%`，但此时拟合 RMS 已经达到 `2.45 mm`，而且不同阈值下平面参数明显漂移。因此不能通过降低 `min_inlier_ratio` 或放宽 RANSAC 阈值强行保存。

进一步按“整帧激光交线”检查，`50` 张中只有 `4` 张能在 `1 mm` 阈值下形成同一平面。该批图片实际由命令行 Gain=15 又手动升到了 Gain=20，并且标定板由手扶持，存在以下风险：

```text
板面弯曲
移动后尚未静止
蓝线覆盖标记角点
标定姿态之间不一致
```

结论：该批数据不可作为正式激光平面标定数据，不能用软件门限把它“变合格”。

### 17.2 标定算法重新设计

`src/calib_laser_plane.py` 不再只执行“所有三维点直接做点级 RANSAC”，而是增加多层约束。

#### 第一层：绿色通道检测标定板

蓝激光会污染普通灰度图中的黑白边缘。标定板检测改为优先使用绿色通道：

```yaml
laser_calibration:
  charuco_detection_channel: "green"
```

激光中心仍从完整 BGR 图像提取。

#### 第二层：排除被激光覆盖的板角点

位姿估计前，排除激光中心 `10 px` 范围内的 ChArUco/ArUco 角点：

```yaml
charuco_laser_exclusion_px: 10
```

这样可以防止蓝线穿过标记边缘后，把整帧板位姿拉偏。

#### 第三层：二维强度与细条带约束

参考另一台电脑能够成功标定的 `calib_laser_plane.py`，接入其有效思想：

```yaml
laser_min_score: 40
stripe_max_dist_px: 2.5
```

处理顺序：

```text
删除响应低于 40 的中心
二维 RANSAC 找主激光条带
删除距主条带超过 2.5 px 的散点
```

没有直接覆盖原文件，原因是外部版本存在两项兼容问题：

```text
cv2.imread 无法可靠读取 Windows 中文路径
blue_laser_score(img, cfg) 与当前函数接口不一致
```

当前版本保留 `imread_color`，并显式传递 `score_mode` 和 `blue_gate_threshold`。

#### 第四层：单帧三维激光交线

平面标定板与激光平面的交集必然是一条三维直线。每帧反投影后先执行三维直线 RANSAC：

```yaml
line_ransac_threshold: 0.001
min_line_inlier_ratio: 0.60
```

偏离三维交线超过 `1 mm` 的局部中心被拒绝，保留点投影回拟合交线，再参与跨帧平面估计。

#### 第五层：整帧共识

新增 `plane_fit.frame_consensus`：

```yaml
frame_consensus:
  enabled: true
  min_point_inlier_ratio: 0.50
  max_median_factor: 1.50
  min_good_frames: 8
  min_good_frame_ratio: 0.50
```

激光平面先由不同板姿态上的整条交线生成候选，再按整帧分类。坏位姿贡献的整条错误线不会因为点数较多而支配最终平面。

### 17.3 安全拒绝原则

新版错误信息会直接输出：

```text

自动拒绝的非共面图片文件名
```

若共识帧不足，不保存激光平面。此时应重新检查板刚性、运动模糊、激光饱和和姿态覆盖，而不是继续放宽门限。

```text
30 px：32 点
40 px：71 点
50 px：接近完整线段
```

因此曲面配置最终调整为：

```yaml
max_width_px: 50
```

该参数只是允许宽响应进入 Steger 定位，不是把整条光晕都当作中心；最终中心仍由 Hessian 脊线做亚像素定位。

九个关键帧在 `50 px` 上限下约得到：

```text
37～97 点/帧
```

### 18.3 第二原因：第二峰比例过严

部分检查图仍存在断点。以 `img_000052` 为例：

```text
当前：69 点
关闭第二峰过滤：87 点
```

曲面散射会在主峰附近形成局部肩峰，`max_secondary_peak_ratio=0.80` 将这些有效行误判为双峰。扫描结果：

```text
0.80：69 点
0.85：87 点
0.90：87 点
```

最终调整为：

```yaml
max_secondary_peak_ratio: 0.85
```

调整后 `check_052` 和 `check_155` 的红点基本覆盖完整激光核心。

## 21. 手动停止行程下的共同覆盖区域验证

### 21.1 完整点云重复性偏差

两次扫描的完整点云结果：

```text
扫描 2：95.053 mm
扫描 3：95.712 mm
直径差：0.660 mm
样本标准差：0.466 mm
```

两次导轨跟踪本身都很好：

```text
center RMS：0.244 / 0.231 mm
重投影：0.982 / 0.978 px
actual/nominal：0.9733 / 0.9727
```

但采集覆盖范围不同：

```text
总帧：442 / 430
轨迹跨度：88.216 / 85.832 mm
跨度相差：2.384 mm
```

半球并非完全球面，且系统误差随视角和深度变化。不同扫描覆盖不同边缘区域时，即使点云局部非常接近，整球拟合半径也会变化。

### 21.2 自动共同覆盖算法

由于当前无法保证完全相同的自动停止行程，验证程序增加共同覆盖模式。默认处理：

```text
每个点云 XYZ 两端各去除 2% 百分位边缘
在 ChArUco 板坐标系求所有扫描的轴对齐公共交集
只在公共区域重新拟合球面
只在公共区域计算双向最近邻差异
不执行 ICP
```

程序同时保留：

```text
共同覆盖区域重复性：主要判定指标
完整点云重复性：暴露起止行程、ROI 和边缘杂点差异
```

不会用共同区域结果覆盖完整点云结果，也不会通过配准移动测量点。

### 21.3 当前数据验证

共同覆盖后：

```text
扫描 2：95.805 mm，保留 31664 点（86.8%）
扫描 3：96.000 mm，保留 31680 点（89.0%）
直径差：0.196 mm
样本标准差：0.138 mm
共同区域球心距离：0.227 mm
双向最近邻中位数：0.161 mm
双向最近邻 RMS：0.272 mm
双向最近邻 P95：0.481 mm
```

与完整点云的 `0.466 mm` 标准差相比，共同覆盖后降到 `0.138 mm`，说明当前重复性限制主要来自起止行程和覆盖范围，而不是严重的坐标系漂移。

### 21.4 达到 0.1 mm 标准差的条件

对于只有两次扫描的情况：

```text
样本标准差 = 两次直径差 / sqrt(2)
```

要满足：

```text
样本标准差 <= 0.1 mm
```

两次拟合直径差必须不超过约：

```text
0.141 mm
```

当前共同区域差值为 `0.196 mm`，已经接近但尚未达到目标。下一轮采集要求：

1. 物体与 ChArUco 板始终保持刚性不动。
2. 复用同一份 `roi_keyframes.json`，不要每次重新绘制 ROI。
3. 曝光、增益、速度、步距、焦距和激光安装保持不变。
4. 起止行程可以不同，但两端都应多扫描一段，保证足够大的公共区域。
5. 激光线尽量在硬件上调窄；`max_width_px=50` 只能解决漏检，不能消除宽光斑造成的材质相关中心偏移。
6. 至少重复 `10` 次后再正式评价标准差；两次结果只能用于快速排错。
7. 继续区分两个目标：

```text
重复性目标：直径样本标准差 <= 0.1 mm
绝对精度目标：平均直径接近 98.9 mm
```

即使共同区域标准差达到 `0.1 mm`，当前平均直径仍偏小约 `3 mm`，绝对尺寸问题仍需通过更高质量内参、激光平面留出验证和深度尺度检查单独解决。
