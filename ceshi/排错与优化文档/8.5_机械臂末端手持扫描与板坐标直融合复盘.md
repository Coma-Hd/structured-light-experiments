# 8.5 复盘：机械臂末端手持扫描、板坐标直融合与 ROI 门控

## 1. 今日目标

在相机与线激光已固连到机械臂末端、机械臂**尚未上电**的条件下，验证：

1. 能否不依赖导轨行程 / 转台编码器，仅靠固定 ChArUco 板做逐帧位姿并重建；
2. 建立独立工作区与采集—检查—ROI—重建流程；
3. 统一全项目标定板参数为新板规格；
4. 排查首轮重建大量丢帧原因，并补齐 ROI 内激光到位门控；
5. 确认两次扫描结果直接放在同一板坐标系下是否可用。

---

## 2. 方案结论：可行

机械臂未上电、手动拖动末端时，**不需要知道两帧之间的移动方向与距离**。

重建路径与现有管线一致：

```text
pose_source: charuco
charuco_tracking.mode: per_frame
```

每帧：

1. 检测 ChArUco → PnP 得板→相机位姿；
2. 提取线激光中心 → 与激光平面求交得相机系 3D 点；
3. 用该帧位姿变换到**板坐标系**并融合。

与导轨 / 转台对比：

| 项目 | 导轨 / 转台 | 机械臂未上电（今日） |
|------|-------------|----------------------|
| 运动已知量 | 行程 mm / 转角 ° | 无 |
| 位姿来源 | 编码器或 `rail_fit` | **逐帧 ChArUco PnP** |
| 相机-激光 | 相对固定 | 相对固定（装在末端） |
| 物体与板 | 固定 | 固定 |
| 尺度 | 编码器或板 | **板方格尺寸** |
| 多扫融合 | 板坐标直拼为主 | **板坐标直拼，不做 ICP** |

今日实测：两次扫描结果直接放到同一板坐标系下观察，**效果还可以**，与项目既定原则一致——板固定时优先直拼，不用 ICP 掩盖误差。

## 4. 新建工作区 `ceshi/上机械臂/`

### 4.1 目录与脚本

```text
ceshi/上机械臂/
  arm_scan.yaml
  README.md

  0_capture.ps1                 # 停稳单拍

```

### 4.2 配置要点

- `pose_source: charuco`，`charuco_tracking.mode: per_frame`
- `rail` / `turntable` 关闭
- 关键帧 ROI 按扫描排序后的 **`frame_index`** 插值（无 `positions.csv` / `angles.csv`）
- 默认相机参数沿用现有习惯：800×600，曝光/增益可在采集界面实时调节

### 4.3 连续连拍能力

`continuous_arm_capture.py` 支持：

- 按时间间隔存图（默认约 250 ms）
- 倒计时后开始连拍
- 板角点不足 / 运动过糊则跳过
- 与 `capture.py` 相同的曝光快捷键：`a` / `e d` / `r f` / `b v`，以及 `l` / `c`

## 5. 核心代码扩展

### 5.1 关键帧 ROI 支持 `frame_index`

原先 ROI 只能按 `distance_mm` 或 `angle_deg` 插值。机械臂无编码器，今日扩展：

- `src/keyframe_roi.py`：读写与插值 `frame_index`
- `scripts/draw_keyframe_roi.py`：`--parameter frame_index`
- `src/reconstruct.py` / `scripts/debug_laser.py`：按帧序号取 ROI

### 5.2 ROI 内激光到位门控 `roi_laser_gate`

问题：激光尚未扫入 ROI 时，框内弱蓝噪声仍可能过低阈值出红点。

处理：ROI 启用后，要求框内峰值与命中行数足够，才抓激光中心。

`arm_scan.yaml` 当前门限：

```yaml
roi_laser_gate:
  enabled: true
  min_peak_score: 100
  min_hit_lines: 20
```

对本相机：噪声峰值约 &lt; 90，真激光核约 200+；门控后“线未进 ROI 不出红点”。

## 6. 首轮重建问题与原因

### 6.1 现象

某次重建日志：

```text
重建完成: 有效 5 帧, 丢弃 29 帧
```

丢弃原因几乎全部是：

```text
跳过(位姿误差 xxx px)
```

误差从约 90 px 到天文数字级；门限为 `max_reproj_error: 2.0 px`。

内参本身正常（约 0.47 px），不是内参文件损坏。

### 6.2 原因分析（结合现场确认）

1. **物体挡住大半标定板** → 可见角点少、偏一侧，PnP 易失败；
2. **桌上另有一块舍弃板**，若仍入画，同字典 ID 可能冲突；
3. **连续拖动连拍**放大运动模糊与角点漂移；
4. **成功的少数帧**，是激光已离开物体主体、打到标定板上之后才过门限 —— 说明真正扫物体的时段位姿大多无效，点云主体贡献不足。

### 6.3 采集改进建议

1. 舍弃板彻底移出视野；
2. 物体只占板边缘一小块，四周留足格子；
3. 先停稳单拍验证位姿，再开慢速连拍；
4. 目标帧同时满足：板可见且角点正确、激光在物体上；
5. 重建前必跑 `1_check_poses.ps1`。

## 8. 与 ICP / 配准的关系

今日两次扫描能直接同坐标系查看，依赖的是：

- 物体与标定板相对不动；
- 每次重建都输出到同一 ChArUco 板坐标系。

因此：

- **不做 ICP** 即可融合观察；
- ICP / FPFH+RANSAC 仅在翻面、板被挪动、坐标系不一致时才作为备选精修；
- 不能用 ICP 掩盖内参、激光平面或位姿失败问题。

## 10. 后续建议

1. 按第 6.3 节改善摆板与采集，提高物体段有效帧比例；
2. 机械臂上电后，可引入 TCP / FK 与 ChArUco 融合，降低逐帧 PnP 抖动；
3. ROI 插值参数可从 `frame_index` 升级为 TCP 行程或姿态参数；
4. 继续用板坐标下、**不做 ICP** 的双向最近邻统计做重复性验收。

## 11. 一句话总结

今天打通了「相机+激光装在机械臂末端、未上电手动拖动」的扫描链路：用固定标定板逐帧求位姿，按帧序号做 ROI，并在 ROI 内等激光真正进入后再抓线；两次扫描结果可直接在同一板坐标系下融合查看，无需 ICP。
